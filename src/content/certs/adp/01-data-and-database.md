ADP 필기 1과목 「데이터 이해」는 객관식 80문항 가운데 10문항입니다. 과목별 40% 미만이 과락이므로 열 문항 중 넷은 맞혀야 하고, 배점이 작다고 버리면 총점 70점을 넘겨도 떨어집니다. 다행히 이 과목은 계산이 없고 용어의 자리를 정확히 아는지만 묻습니다. 이 노트는 그중 앞쪽 절반 — 데이터라는 낱말의 정의부터 기업과 사회가 실제로 굴리는 데이터베이스까지를 다룹니다.

## 데이터에서 지혜까지

**데이터**는 다른 것과의 관계를 따지지 않고 그 자체로 존재하는 객관적 사실입니다. 이것을 데이터의 **존재적 특징**이라 부르고, 추론·예측·전망·추정의 근거로 쓰인다는 쓰임새 쪽을 **당위적 특징**이라 부릅니다. 같은 「25도」라는 값이 온도계에 찍혀 있으면 존재적 특징이고, 그것을 근거로 에어컨을 켜면 당위적 특징이 드러난 것입니다.

데이터는 두 축으로 갈립니다. 언어와 문자로 서술한 것이면 **정성적 데이터**, 수치·기호·도형으로 적힌 것이면 **정량적 데이터**입니다. 정성적 데이터는 형태가 제각각이라 저장과 분석에 비용이 더 듭니다. 다른 축은 구조입니다. 여기서 구조란 값이 들어갈 자리와 그 자리의 이름이 미리 정해져 있는 것을 말합니다.

| 유형 | 구조 | 구조가 어디에 있나 | 예 |
| --- | --- | --- | --- |
| 정형 | 행과 열이 고정 | 데이터 밖(스키마)에 따로 | 관계형 데이터베이스 테이블, CSV |
| 반정형 | 느슨한 구조 | 데이터 안에 함께 | XML, JSON, 웹 로그, 센서 데이터 |
| 비정형 | 없음 | 없음 | 텍스트 문서, 이미지, 동영상, 음성 |

데이터를 가공해 관계를 붙이면 정보, 정보를 구조화해 규칙으로 만들면 지식, 거기에 근본 원리를 더하면 지혜입니다. 이 네 층을 아래에서 위로 쌓은 것이 **DIKW 피라미드**입니다.

| 층 | 무엇인가 | 예 |
| --- | --- | --- |
| 데이터(Data) | 가공되지 않은 객관적 사실 | A마트는 볼펜을 1,000원, B마트는 1,200원에 판다 |
| 정보(Information) | 데이터를 가공해 얻은 의미 | A마트의 볼펜이 B마트보다 싸다 |
| 지식(Knowledge) | 정보를 구조화해 얻은 판단 | 볼펜은 A마트에서 사는 것이 좋겠다 |
| 지혜(Wisdom) | 근본 원리를 더한 창의적 아이디어 | A마트는 다른 상품도 B마트보다 쌀 것이다 |

경계가 헷갈릴 때는 화살표의 방향을 봅니다. 관측한 사실을 그대로 옮겼으면 데이터, 둘 이상을 견줘 의미를 붙였으면 정보, 그래서 무엇을 할지 정했으면 지식, 관측하지 않은 대상까지 미루어 짐작했으면 지혜입니다.

## 데이터베이스라는 묶음

**데이터베이스**는 여러 사람이 함께 쓰려고 체계적으로 정리해 통합 관리하는 데이터의 묶음입니다. 성질이 넷입니다.

| 성질 | 뜻 |
| --- | --- |
| 통합된 데이터 | 같은 내용의 중복을 없애 하나로 모은 것 |
| 저장된 데이터 | 컴퓨터가 접근할 수 있는 매체에 담긴 것 |
| 공용 데이터 | 여러 사용자가 서로 다른 목적으로 나눠 쓰는 것 |
| 변화되는 데이터 | 삽입·삭제·갱신으로 상태가 계속 달라지는 것 |

여기서 한 걸음 더 들어가면 운영 관점의 특징 넷이 따로 있습니다. 질의에 수 초 안에 응답하는 **실시간 접근성**, 갱신이 일어나도 항상 현재의 정확한 값을 유지하는 **계속적인 변화**, 여러 사용자가 동시에 같은 데이터를 쓰는 **동시 공용**, 그리고 저장된 주소나 위치가 아니라 값이 무엇인지로 찾아가는 **내용에 의한 참조**입니다. 마지막 것이 가장 자주 나옵니다 — 「3번째 레코드」가 아니라 「나이가 30인 행」으로 부르는 방식입니다.

**DBMS**는 그 데이터베이스를 만들고 다루고 지키는 소프트웨어이고, **SQL**은 DBMS에 일을 시키는 표준 질의 언어입니다. 하는 일에 따라 셋으로 갈립니다.

```sql
CREATE TABLE member (id INT, name VARCHAR(20));  -- 정의(DDL)
INSERT INTO member VALUES (1, '김팔딘');          -- 조작(DML)
GRANT SELECT ON member TO analyst;               -- 제어(DCL)
```

## 처리하는 시스템과 분석하는 시스템

같은 데이터베이스라도 무엇을 위해 세웠는지에 따라 설계가 갈립니다. **OLTP**(Online Transaction Processing)는 주문·입금 같은 업무 거래를 그때그때 처리하는 시스템이고, **OLAP**(Online Analytical Processing)은 쌓인 데이터를 여러 각도에서 집계해 보는 분석용 시스템입니다.

| 견줄 것 | OLTP | OLAP |
| --- | --- | --- |
| 목적 | 거래 처리 | 의사결정 지원 |
| 다루는 단위 | 한 건의 트랜잭션 | 집계된 요약 |
| 데이터 시점 | 현재 | 현재와 과거 |
| 질의 성격 | 짧고 정해진 질의가 대량 | 길고 복잡한 질의가 소량 |
| 갱신 | 삽입·수정·삭제가 잦다 | 주로 읽기, 일괄 적재 |
| 설계 | 정규화해 중복을 줄인다 | 비정규화를 허용해 조회를 빠르게 한다 |

OLAP이 데이터를 보는 방식에는 이름이 붙어 있습니다. 요약 수준을 한 단계 내려 자세히 보면 **드릴다운**, 반대로 올려 뭉치면 **롤업**, 축을 돌려 보는 각도를 바꾸면 **피벗**, 특정 값으로 잘라 한 면만 보면 **슬라이싱**입니다.

## 웨어하우스와 마트

**데이터웨어하우스**(DW)는 여러 시스템에 흩어진 데이터를 분석 목적으로 한곳에 모아 둔 저장소입니다. 네 가지 성질로 정의합니다.

| 성질 | 뜻 |
| --- | --- |
| 주제 지향적 | 업무 기능이 아니라 「고객」·「매출」 같은 분석 주제로 묶는다 |
| 통합적 | 시스템마다 다른 코드와 단위를 하나로 맞춘다 |
| 시계열적 | 시점을 붙여 과거 이력을 그대로 남긴다 |
| 비휘발적 | 한 번 적재하면 고치거나 지우지 않고 읽기만 한다 |

비휘발적이라는 말이 OLTP와 가장 크게 갈리는 지점입니다. 운영 시스템에서 고객의 주소가 바뀌면 옛 주소는 사라지지만, 웨어하우스는 바뀐 사실 자체를 새 행으로 남깁니다.

**데이터마트**(DM)는 그 웨어하우스에서 특정 부서나 주제에 필요한 부분만 떼어 낸 작은 저장소입니다. 웨어하우스를 먼저 세우고 마트를 잘라 내는 방식과, 부서별 마트를 먼저 만들고 나중에 통합하는 방식이 둘 다 쓰입니다.

| 견줄 것 | 데이터웨어하우스 | 데이터마트 |
| --- | --- | --- |
| 범위 | 전사 | 부서·주제 단위 |
| 데이터 크기 | 크다 | 작다 |
| 구축 기간 | 길다 | 짧다 |
| 주제 | 여럿 | 하나 |

운영 시스템과 웨어하우스 사이에 **ODS**(Operational Data Store)를 두기도 합니다. 여러 원천에서 막 뽑아 온 데이터를 통합해 잠시 두는 자리이고, 웨어하우스와 달리 최신 상태로 계속 갱신됩니다.

## 기업 안팎을 잇는 시스템

**CRM**(고객관계관리)은 고객과의 접점에서 생기는 데이터를 모아 고객을 이해하고 관계를 관리하는 시스템입니다. 시선이 기업 안쪽, 정확히는 기업과 고객 사이를 향합니다. **SCM**(공급망관리)은 원자재 조달부터 생산·유통·납품까지 공급 사슬 전체를 관리하는 시스템이라 시선이 기업 바깥, 협력사와 물류를 향합니다. **ERP**(전사적자원관리)는 인사·회계·생산·구매 같은 사내 자원을 한 시스템에서 통합 관리합니다.

| 시스템 | 관리 대상 | 방향 |
| --- | --- | --- |
| CRM | 고객과의 관계 | 기업 → 고객 |
| SCM | 공급망과 물류 | 기업 → 협력사·유통 |
| ERP | 사내 자원(인사·회계·생산) | 기업 안 |

이 셋이 각자 데이터를 쌓으면 시스템 사이를 이어 줄 것이 필요해집니다. 그 자리를 **EAI**(Enterprise Application Integration)가 맡습니다 — 애플리케이션끼리 직접 연결하는 대신 가운데 허브를 두고 형식을 바꿔 주고받게 만드는 통합 방식입니다. 여기서 모인 데이터가 웨어하우스로 흘러가면 **EDW**(전사적 데이터웨어하우스)가 되고, 그 위에서 보고서와 지표를 뽑는 것이 **BI**(비즈니스 인텔리전스)입니다. 자세한 연계 방식은 2과목에서 따로 다룹니다.

## 분야별로 이름이 다른 데이터베이스

같은 데이터베이스 기술이 분야마다 다른 이름을 달고 나옵니다. ADP는 이 이름과 분야를 짝지어 묻습니다. 크게 기업 부문 셋과 사회기반구조 다섯으로 나뉩니다.

| 부문 | 자주 나오는 시스템 |
| --- | --- |
| 제조 | SCM, ERP, CRM, 실시간 기업(RTE) |
| 금융 | EAI, ERP, e-CRM, EDW |
| 유통 | KMS(지식관리시스템), RFID, SCM |
| 물류 | CVO(첨단화물운송), EDI(전자문서교환), PORT-MIS(항만운영정보) |
| 지리 | GIS(지리정보), LBS(위치기반서비스), SIM(공간정보관리) |
| 교통 | ITS(지능형교통), GIS-T(교통지리정보) |
| 의료 | HIS(병원정보), PACS(의료영상저장전송), U-Health |
| 교육 | NEIS(교육행정정보), e-Campus |

외우는 요령은 이름 안의 첫 낱말입니다. C로 시작하는 CVO는 화물(Cargo), G로 시작하는 GIS는 지리(Geographic), P로 시작하는 PACS는 영상(Picture)입니다. 이 절은 다섯 보기 중 분야와 시스템의 짝이 어긋난 것을 고르게 하는 형태로 가장 자주 나오고, 어긋나는 자리는 대개 유통과 물류 사이 또는 지리와 교통 사이에 심어 둡니다.

## 연습 문제

1. 다음 설명이 가리키는 DIKW의 층은?\
   「지난 세 달 동안 A마트가 늘 B마트보다 쌌으므로, 아직 확인하지 않은 다른 품목도 A마트가 쌀 것이다」\
   ① 데이터\
   ② 정보\
   ③ 지식\
   ④ 지혜

   답. ④. 확인하지 않은 대상까지 미루어 짐작했으므로 지혜입니다. 세 달치 가격 비교 자체는 정보이고, 「A마트에서 사자」까지가 지식입니다.
2. 데이터베이스의 특징 중 「내용에 의한 참조」를 바르게 설명한 것은?\
   ① 여러 사용자가 동시에 같은 데이터를 쓸 수 있다\
   ② 저장된 물리적 주소가 아니라 값으로 데이터를 찾는다\
   ③ 갱신이 일어나도 항상 최신 상태를 유지한다\
   ④ 질의에 수 초 안에 응답한다

   답. ②. ①은 동시 공용, ③은 계속적인 변화, ④는 실시간 접근성입니다.
3. OLTP와 OLAP을 견준 것으로 옳지 않은 것은?\
   ① OLTP는 짧고 정해진 질의가 대량으로 들어온다\
   ② OLAP은 현재와 과거 데이터를 함께 다룬다\
   ③ OLTP는 조회 속도를 위해 비정규화를 적극 허용한다\
   ④ OLAP은 삽입·수정보다 읽기가 압도적으로 많다

   답. ③. 비정규화를 허용하는 쪽은 OLAP입니다. OLTP는 중복을 줄이려고 정규화합니다.
4. 데이터웨어하우스의 네 성질 가운데, 운영 시스템에서 고객 주소가 바뀌어도 옛 주소가 그대로 남는 이유에 해당하는 것은?\
   ① 주제 지향적\
   ② 통합적\
   ③ 시계열적이고 비휘발적\
   ④ 실시간 접근성

   답. ③. 시점을 붙여 이력을 남기고(시계열적), 적재한 값을 고치지 않기(비휘발적) 때문입니다. ④는 데이터베이스 일반의 특징이라 웨어하우스의 네 성질에 들어가지 않습니다.
5. 분야와 시스템의 짝으로 옳지 않은 것은?\
   ① 물류 — CVO\
   ② 지리 — GIS\
   ③ 의료 — NEIS\
   ④ 유통 — RFID

   답. ③. NEIS는 교육행정정보시스템으로 교육 부문입니다. 의료 쪽은 HIS·PACS·U-Health입니다.
6. 서술형 연습입니다. CRM과 SCM이 각각 무엇을 관리하는 시스템인지 밝히고, 둘이 다루는 데이터가 어떻게 다른지 한 가지만 들어 5줄 이내로 쓰시오.

   답. 채점 기준은 셋입니다. (1) CRM을 고객 접점에서 생기는 데이터로 고객을 이해하고 관계를 관리하는 시스템이라고 정의했는가. (2) SCM을 조달·생산·유통·납품에 이르는 공급 사슬 전체를 관리하는 시스템이라고 정의했는가. (3) 데이터의 차이를 하나라도 구체적으로 들었는가 — 예를 들어 CRM은 구매 이력·상담 기록처럼 개별 고객 단위로 쌓이는 반면 SCM은 재고 수량·리드타임·운송 상태처럼 품목과 거점 단위로 쌓인다는 식입니다. 정의 둘에 각각 배점이 있고 마지막 한 가지가 나머지 배점이므로, 셋 중 하나라도 빠지면 부분점수만 붙습니다.

객관식 열 문항 중 이 노트의 범위에서 서너 문항이 나옵니다. 문제는 대체로 「짝이 어긋난 것 고르기」와 「정의 하나 고르기」 둘 중 하나이므로, 표의 왼쪽 열과 오른쪽 열을 가리고 서로 불러 보는 연습이 그대로 대비가 됩니다.
