[앞 노트](/learn/certs/sqld/09-character-number-date-functions)의 함수는 값을 자르고 다듬었습니다. 이번 노트의 함수는 값의 **타입을 바꾸거나**, 값이 비었을 때 대신 쓸 것을 정하거나, 조건에 따라 다른 값을 고릅니다. 셋 다 결과를 직접 써 보게 하는 꼴로 물을 수 있고, 특히 NULL 관련 함수는 이름이 비슷해 인자 순서를 헷갈리기 쉽습니다.

예제는 지금까지 쓴 사원 테이블입니다.

| 사원명 | 부서코드 | 급여 | 상여 |
| --- | --- | --- | --- |
| 홍길동 | D01 | 300 | 50 |
| 김철수 | D01 | 250 | NULL |
| 이영희 | D02 | 400 | 100 |
| 박민수 | D02 | 350 | NULL |

## 형변환

### 명시적 형변환과 암시적 형변환

**형변환**은 값의 데이터 타입을 다른 타입으로 바꾸는 일입니다. 바꾸는 방법이 둘입니다. 변환 함수를 직접 적어 바꾸는 것이 **명시적 형변환**이고, 적지 않았는데 데이터베이스가 비교나 연산을 하려고 알아서 바꾸는 것이 **암시적 형변환**입니다.

| 구분 | 명시적 형변환 | 암시적 형변환 |
| --- | --- | --- |
| 누가 바꾸나 | 쓰는 사람이 함수로 | 데이터베이스가 스스로 |
| 예 | `TO_NUMBER('100') + 1` | `'100' + 1` |
| 위험 | 적은 대로 동작한다 | 성능 저하나 오류가 숨어 있다 |

`'100' + 1`은 Oracle에서 오류 없이 101이 나옵니다. 문자 `'100'`을 숫자로 바꿔 더한 것입니다. 편해 보이지만 언제 어느 쪽을 바꿀지를 데이터베이스가 정하므로, 결과를 예측하려면 변환 함수를 적는 쪽이 안전합니다.

### 암시적 형변환이 일어나는 자리

암시적 형변환에서 무엇이 바뀌느냐가 성능을 가릅니다. 사번이 문자 컬럼인데 `WHERE 사번 = 123`처럼 숫자로 비교하면, Oracle은 숫자를 문자로 바꾸지 않고 컬럼 쪽을 숫자로 바꿉니다. 컬럼에 `TO_NUMBER`를 씌운 것과 같아져 그 컬럼의 인덱스를 못 쓰게 됩니다. 반대로 숫자 컬럼을 `'123'`과 비교하면 바뀌는 쪽이 상수라 인덱스에 영향이 없습니다. 앞 노트 끝에서 예고한 「컬럼을 함수로 감싸면 인덱스를 못 쓴다」가 바로 이 자리입니다.

## 변환 함수

### TO_CHAR

`TO_CHAR(값, 형식)`는 숫자나 날짜를 형식에 맞춘 문자로 바꿉니다. 날짜 형식은 `YYYY`(연), `MM`(월), `DD`(일), `HH24`(24시간제 시), `MI`(분), `SS`(초)로 적습니다. 분을 `MM`으로 적으면 월이 나온다는 것이 헷갈리는 자리입니다.

```sql
SELECT TO_CHAR(DATE '2026-10-28', 'YYYY/MM/DD') FROM DUAL;
-- 2026/10/28
SELECT TO_CHAR(1234567, '9,999,999') FROM DUAL;
-- 1,234,567
```

숫자 형식의 `9`는 한 자리를 뜻하고 `0`은 빈자리를 0으로 채웁니다. `DUAL`은 Oracle이 계산 한 줄을 보려고 두는 한 행짜리 테이블입니다.

### TO_DATE와 TO_NUMBER

`TO_DATE(문자, 형식)`는 문자를 형식대로 읽어 날짜로 만들고, `TO_NUMBER(문자, 형식)`는 숫자로 만듭니다. 형식은 문자가 지금 어떤 모양인지를 알려 주는 것이라 문자와 맞아야 합니다. `TO_DATE('20261028', 'YYYYMMDD')`는 되지만 `TO_DATE('2026-10-28', 'YYYYMMDD')`는 구분자가 맞지 않아 오류입니다. `TO_NUMBER('1,234', '9,999')`는 1234입니다.

세 함수의 방향을 한 줄로 묶으면 `TO_CHAR`는 숫자·날짜에서 문자로, `TO_DATE`와 `TO_NUMBER`는 문자에서 날짜·숫자로 갑니다. 숫자와 날짜 사이를 곧바로 잇는 함수는 없고 문자를 거칩니다.

### 형변환이 없어 생기는 오류

변환 함수를 안 적고 암시적 형변환에 맡기면 데이터에 따라 오류가 납니다.

- 문자 컬럼 사번에 `'A12'` 같은 값이 한 행이라도 있으면 `WHERE 사번 = 123`은 그 행을 숫자로 바꾸지 못해 **수치 변환 오류**로 문장 전체가 멈춥니다. 다른 행이 전부 숫자여도 마찬가지입니다.
- 날짜 컬럼을 `WHERE 입사일 = '2026-10-28'`처럼 문자와 비교하면 세션의 기본 날짜 형식에 따라 되기도 하고 오류가 나기도 합니다. `TO_DATE('2026-10-28', 'YYYY-MM-DD')`로 적으면 환경과 상관없이 같습니다.

## NULL 관련 함수

### NVL과 NVL2

NULL은 연산에 끼면 결과를 NULL로 만들므로, 비었을 때 대신 쓸 값을 정하는 함수가 따로 있습니다.

- `NVL(식, 대체값)` — 식이 NULL이면 대체값, 아니면 식 그대로입니다. `급여 + NVL(상여, 0)`은 김철수에게 250을 돌려줍니다. NVL 없이 `급여 + 상여`로 적으면 NULL입니다.
- `NVL2(식, 값1, 값2)` — 식이 NULL이 **아니면** 값1, NULL이면 값2입니다. `NVL2(상여, '있음', '없음')`은 홍길동에게 `'있음'`, 김철수에게 `'없음'`입니다.

NVL2는 셋째 인자가 NULL일 때의 값이라는 점이 순서를 헷갈리게 하는 자리입니다. 「아니면 둘째, 맞으면 셋째」로 읽습니다. SQL Server에서 NVL에 해당하는 함수는 `ISNULL`입니다.

### NULLIF와 COALESCE

- `NULLIF(값1, 값2)` — 두 값이 같으면 NULL, 다르면 값1입니다. `NULLIF(급여, 300)`은 홍길동에게 NULL, 나머지에게 원래 급여입니다. 0으로 나누기를 피할 때 `금액 / NULLIF(수량, 0)`처럼 씁니다.
- `COALESCE(값1, 값2, …)` — 인자를 앞에서부터 보며 NULL이 아닌 첫 값을 돌려주고, 전부 NULL이면 NULL입니다. 인자 수에 제한이 없어 두 인자짜리 `COALESCE(상여, 0)`은 `NVL(상여, 0)`과 같은 결과입니다.

| 식 | 홍길동(상여 50) | 김철수(상여 NULL) |
| --- | --- | --- |
| `NVL(상여, 0)` | 50 | 0 |
| `NVL2(상여, 1, 0)` | 1 | 0 |
| `NULLIF(상여, 50)` | NULL | NULL |
| `COALESCE(상여, 급여, 0)` | 50 | 250 |

`NULLIF(상여, 50)`이 김철수에게도 NULL인 이유는 상여가 이미 NULL이라 값1을 그대로 돌려주기 때문입니다.

## DECODE와 CASE

### DECODE

`DECODE(식, 값1, 결과1, 값2, 결과2, …, 기본값)`는 식을 값들과 차례로 견주어 같은 짝의 결과를 돌려주는 Oracle 함수입니다. 맞는 값이 없으면 기본값이고, 기본값을 안 적으면 NULL입니다.

```sql
SELECT 사원명, DECODE(부서코드, 'D01', '영업', 'D02', '개발', '기타')
  FROM 사원;
```

DECODE는 같다 비교만 하므로 「급여가 300 이상이면」 같은 범위 조건은 못 적습니다. 그리고 DECODE는 NULL과 NULL을 같다고 봅니다 — `DECODE(상여, NULL, '없음', '있음')`은 김철수에게 `'없음'`입니다. `=`로는 NULL을 못 찾았던 것과 다른 동작입니다.

### 단순 CASE와 검색 CASE

`CASE` 식은 표준 SQL이라 Oracle과 SQL Server에서 모두 쓰고, 모양이 둘입니다.

```sql
-- 단순 CASE: 식 하나를 값들과 같다로 견준다
CASE 부서코드 WHEN 'D01' THEN '영업'
              WHEN 'D02' THEN '개발'
              ELSE '기타' END

-- 검색 CASE: WHEN마다 조건을 따로 쓴다
CASE WHEN 급여 >= 350 THEN '상'
     WHEN 급여 >= 300 THEN '중'
     ELSE '하' END
```

| 구분 | 단순 CASE | 검색 CASE |
| --- | --- | --- |
| `CASE` 뒤 | 비교할 식 | 아무것도 없음 |
| `WHEN` 뒤 | 값 | 조건 |
| 범위 조건 | 못 쓴다 | 쓴다 |

### CASE의 평가 규칙

`WHEN`은 위에서부터 보고 처음 참이 된 자리에서 멈춥니다. 위 검색 CASE에서 이영희(400)는 첫 조건에서 `'상'`이 되고 둘째 조건은 보지 않습니다. 순서를 바꿔 `급여 >= 300`을 먼저 두면 350과 400이 모두 `'중'`이 되어 `'상'`이 하나도 안 나옵니다. 맞는 `WHEN`이 없고 `ELSE`도 없으면 NULL입니다.

NULL을 찾을 때는 단순 CASE를 쓸 수 없습니다. `CASE 상여 WHEN NULL THEN …`은 `상여 = NULL`로 견주는 셈이라 언제나 맞지 않으므로, `CASE WHEN 상여 IS NULL THEN …`처럼 검색 CASE로 적습니다.

## 연습 문제

1. 형변환에 대한 설명으로 옳지 않은 것은?\
   ① 변환 함수를 적어 바꾸는 것을 명시적 형변환이라 한다\
   ② 암시적 형변환은 데이터베이스가 스스로 타입을 바꾸는 것이다\
   ③ 문자 컬럼을 숫자 상수와 비교하면 컬럼 쪽이 바뀌어 인덱스를 못 쓸 수 있다\
   ④ 암시적 형변환은 데이터에 상관없이 오류가 나지 않는다

   답. ④. 숫자로 바꿀 수 없는 값이 한 행이라도 있으면 수치 변환 오류가 납니다.
2. 다음 중 오류가 나는 것은?\
   ① `TO_DATE('20261028', 'YYYYMMDD')`\
   ② `TO_DATE('2026-10-28', 'YYYYMMDD')`\
   ③ `TO_CHAR(DATE '2026-10-28', 'YYYY')`\
   ④ `TO_NUMBER('1,234', '9,999')`

   답. ②. 형식에는 구분자가 없는데 문자에는 하이픈이 있어 읽지 못합니다.
3. `TO_CHAR(DATE '2026-10-28', 'YYYY-MM-DD HH24:MM')`에 대한 설명으로 옳은 것은?\
   ① 마지막 `MM` 자리에 분이 나온다\
   ② 마지막 `MM` 자리에 월이 나온다\
   ③ 오류가 난다\
   ④ `HH24`는 12시간제 시를 뜻한다

   답. ②. 분은 `MI`입니다. `MM`은 어디에 적어도 월이라 시각 뒤에 10이 다시 찍힙니다.
4. 상여가 NULL인 김철수(급여 250)에게 `NVL2(상여, 급여 + 상여, 급여)`의 결과는?\
   ① NULL\
   ② 0\
   ③ 250\
   ④ 오류

   답. ③. 상여가 NULL이므로 셋째 인자인 급여 250을 돌려줍니다.
5. 다음 식의 결과를 차례로 바르게 적은 것은?

   ```sql
   NULLIF(10, 10), NULLIF(10, 20), COALESCE(NULL, NULL, 5, 7)
   ```

   ① NULL, 10, 5\
   ② 10, NULL, 7\
   ③ NULL, 20, 5\
   ④ 0, 10, 5

   답. ①. 같으면 NULL, 다르면 첫째 값 10이고, COALESCE는 NULL이 아닌 첫 값 5를 돌려줍니다.
6. 급여 350인 박민수에게 다음 식의 결과는?

   ```sql
   CASE WHEN 급여 >= 300 THEN 'B'
        WHEN 급여 >= 350 THEN 'A'
        ELSE 'C' END
   ```

   ① `'A'`\
   ② `'B'`\
   ③ `'C'`\
   ④ NULL

   답. ②. 첫 `WHEN`에서 이미 참이 되어 멈추므로 둘째 조건은 보지 않습니다.
7. `DECODE`와 `CASE`에 대한 설명으로 옳은 것은?\
   ① `DECODE`는 범위 조건을 쓸 수 있다\
   ② 단순 CASE로 `WHEN NULL`을 적으면 NULL인 행을 찾는다\
   ③ `DECODE`에서 기본값을 빼고 맞는 값이 없으면 NULL이다\
   ④ `CASE`는 Oracle 전용 문법이다

   답. ③. `DECODE`는 같다 비교만 하고, 단순 CASE는 `=`로 견주어 NULL을 못 찾으며, `CASE`는 표준 SQL입니다.
8. 사원 테이블 네 행에서 행마다 `급여 + 상여`를 구했을 때 NULL이 나오는 행의 수는?\
   ① 0\
   ② 1\
   ③ 2\
   ④ 4

   답. ③. 상여가 NULL인 김철수와 박민수 두 행은 덧셈 결과가 NULL입니다. `NVL(상여, 0)`으로 감싸면 0행이 됩니다.

다음 노트에서는 행을 묶는 집계 함수와 `GROUP BY`·`HAVING`으로 갑니다. 이 노트의 NULL 처리 함수가 거기서 다시 쓰입니다 — 집계 함수는 NULL을 건너뛰므로, 평균에 NULL을 0으로 넣고 싶으면 `NVL`로 먼저 바꿔야 결과가 달라집니다.
