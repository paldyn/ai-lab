[앞 노트](/learn/certs/sqld/11-aggregate-functions-group-by-having)까지 `SELECT` 문의 절을 하나씩 붙여 왔습니다. 남은 것은 결과를 어떤 차례로 늘어놓을지 정하는 `ORDER BY`입니다. 그리고 절이 다 모였으니, 적는 순서와 다르게 돌아가는 **처리 순서**를 한 줄로 정리할 수 있습니다. 앞 노트에서 「왜 안 되는가」로 남겨 둔 자리들이 이 순서 하나로 풀립니다.

예제는 앞 노트의 여섯 행짜리 사원 테이블입니다.

| 사원명 | 부서코드 | 급여 | 상여 |
| --- | --- | --- | --- |
| 홍길동 | D01 | 300 | 50 |
| 김철수 | D01 | 250 | NULL |
| 이영희 | D02 | 400 | 100 |
| 박민수 | D02 | 350 | NULL |
| 최지은 | D03 | 200 | 30 |
| 정대현 | NULL | 280 | NULL |

## ORDER BY 절

### ASC와 DESC

`ORDER BY`는 `SELECT` 문의 맨 끝에 적어 결과 행의 차례를 정합니다. 컬럼 뒤에 `ASC`(오름차순, 작은 값부터)나 `DESC`(내림차순, 큰 값부터)를 붙이고, 아무것도 안 붙이면 `ASC`로 봅니다.

```sql
SELECT 사원명, 급여 FROM 사원 ORDER BY 급여;
-- 최지은 200 / 김철수 250 / 정대현 280 / 홍길동 300 / 박민수 350 / 이영희 400
```

숫자는 크기, 문자는 사전 순서, 날짜는 이른 날짜가 작은 값입니다. `ORDER BY`를 안 적으면 결과의 차례는 정해져 있지 않습니다. 입력한 순서대로 나올 것 같지만 그런 약속은 없고, 앞 노트에서 본 것처럼 `GROUP BY`도 정렬을 약속하지 않습니다.

### 정렬과 결과 행

`ORDER BY`는 행을 늘어놓는 차례만 바꾸고 행을 더하거나 빼지 않습니다. 그래서 「결과 행 수」를 묻는 문항에서는 `ORDER BY`를 지우고 세어도 답이 같습니다. 대신 「세 번째 행의 값」처럼 자리를 묻는 문항에서는 정렬이 답을 정합니다.

## 정렬 기준을 적는 법

### 컬럼 이름과 별칭

정렬 기준은 컬럼 이름 외에 `SELECT`에서 붙인 별칭으로도 적을 수 있습니다. 식에 별칭을 붙였다면 그 식을 다시 적을 필요가 없습니다.

```sql
SELECT 사원명, 급여 * 12 AS 연봉
  FROM 사원
 ORDER BY 연봉 DESC;
```

그리고 `SELECT` 목록에 없는 컬럼으로도 정렬할 수 있습니다. `SELECT 사원명 FROM 사원 ORDER BY 급여`는 급여를 화면에 안 보이고도 급여 차례로 이름을 늘어놓습니다. 다만 `GROUP BY`를 쓴 문장에서는 정렬 기준도 그룹 기준 컬럼이나 집계 함수여야 합니다 — 그룹을 만든 뒤에는 개별 행의 값이 남아 있지 않기 때문입니다.

### 컬럼 번호

`ORDER BY 2`처럼 숫자를 적으면 `SELECT` 목록에서 그 자리에 있는 컬럼으로 정렬합니다. 테이블의 컬럼 순서가 아니라 **`SELECT` 목록의 자리**라는 점이 갈리는 지점입니다.

```sql
SELECT 사원명, 급여, 상여 FROM 사원 ORDER BY 2 DESC;
-- 둘째 자리인 급여로 내림차순
```

목록에 셋밖에 없는데 `ORDER BY 4`를 적으면 오류입니다. 이름·별칭·번호는 한 `ORDER BY` 안에 섞어 적어도 됩니다.

## NULL의 정렬 위치

### Oracle과 SQL Server

NULL은 값이 아니라서 크고 작음이 없지만, 정렬할 때는 어딘가에 놓아야 합니다. 제품마다 보는 방식이 반대입니다.

| 제품 | NULL을 보는 방식 | `ASC`에서 | `DESC`에서 |
| --- | --- | --- | --- |
| Oracle | 가장 큰 값 | 맨 뒤 | 맨 앞 |
| SQL Server | 가장 작은 값 | 맨 앞 | 맨 뒤 |

Oracle에서 `ORDER BY 상여`는 30·50·100 다음에 NULL인 김철수·박민수·정대현이 오고, `ORDER BY 상여 DESC`는 NULL 셋이 맨 앞에 선 뒤 100·50·30입니다. NULL끼리의 차례는 정해져 있지 않습니다. 그래서 보기가 NULL인 행의 이름을 하나로 못 박아 묻는다면, 그 셋 중 누가 먼저인지는 답이 될 수 없다는 점까지 따져야 합니다.

### NULLS FIRST와 NULLS LAST

Oracle에서는 기본 위치를 바꿀 수 있습니다. 정렬 방향 뒤에 `NULLS FIRST`를 붙이면 NULL을 맨 앞에, `NULLS LAST`를 붙이면 맨 뒤에 둡니다. `ORDER BY 상여 DESC NULLS LAST`는 100·50·30 다음에 NULL이 옵니다. 내림차순으로 큰 상여부터 보고 싶은데 NULL이 위를 가리는 일을 막을 때 씁니다.

## 여러 컬럼으로 정렬하기

### 앞 기준이 같을 때만

정렬 기준을 쉼표로 여럿 적으면 첫째 기준으로 먼저 늘어놓고, 첫째 값이 같은 행끼리만 둘째 기준으로 다시 늘어놓습니다.

```sql
SELECT 부서코드, 사원명, 급여
  FROM 사원
 ORDER BY 부서코드, 급여 DESC;
-- D01  홍길동  300
-- D01  김철수  250
-- D02  이영희  400
-- D02  박민수  350
-- D03  최지은  200
-- NULL 정대현  280
```

부서코드는 오름차순이라 Oracle에서 NULL인 정대현이 맨 끝에 서고, 같은 부서 안에서만 급여가 큰 사람이 먼저 옵니다.

### 방향은 컬럼마다

`ASC`·`DESC`는 바로 앞의 컬럼 하나에만 걸립니다. 위 문장의 `DESC`는 급여에만 걸리고 부서코드는 기본값인 `ASC`입니다. 둘 다 내림차순이 되게 하려면 `ORDER BY 부서코드 DESC, 급여 DESC`처럼 컬럼마다 적어야 합니다. 「`DESC`를 맨 끝에 한 번 적으면 모든 기준에 적용된다」는 보기는 틀린 문장입니다.

## SELECT 문 실행 순서

### 적는 순서와 처리 순서

`SELECT` 문은 `SELECT`부터 적지만 데이터베이스가 처리하는 순서는 다릅니다.

| 처리 순서 | 절 | 하는 일 |
| --- | --- | --- |
| 1 | `FROM` | 읽을 테이블을 정한다 |
| 2 | `WHERE` | 행을 거른다 |
| 3 | `GROUP BY` | 행을 그룹으로 묶는다 |
| 4 | `HAVING` | 그룹을 거른다 |
| 5 | `SELECT` | 보일 컬럼과 식을 계산하고 별칭을 붙인다 |
| 6 | `ORDER BY` | 결과를 늘어놓는다 |

적는 순서는 `SELECT` → `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `ORDER BY`이고, 처리 순서에서는 `SELECT`가 다섯째로 내려갑니다. 두 순서를 나란히 놓고 어느 쪽이 처리 순서인지 고르게 하는 꼴로 물을 수 있으니, `SELECT`가 어디에 서 있는지부터 봅니다.

### 순서가 설명하는 규칙

앞 노트들에서 따로 외운 규칙이 이 표 한 장에서 나옵니다.

- `ORDER BY`에서 별칭을 쓸 수 있는 이유 — 별칭은 5번 `SELECT`에서 생기고 `ORDER BY`는 그 뒤인 6번이라 이미 있는 이름을 씁니다.
- `WHERE`·`GROUP BY`·`HAVING`에서 별칭을 못 쓰는 이유 — 셋 다 5번보다 앞이라 별칭이 아직 없습니다.
- `WHERE`에 집계 함수를 못 쓰는 이유 — 2번 시점에는 3번의 그룹이 아직 없습니다.
- `HAVING`에 집계 함수를 쓸 수 있는 이유 — 4번은 3번 뒤라 그룹이 이미 있습니다.

규칙을 하나씩 외우는 대신, 보기의 문장에서 어떤 이름이나 값이 그 절의 시점에 이미 만들어져 있는지를 따지면 됩니다.

## 연습 문제

1. `ORDER BY`에 대한 설명으로 옳지 않은 것은?\
   ① 정렬 방향을 적지 않으면 오름차순이다\
   ② `SELECT` 목록에 없는 컬럼으로도 정렬할 수 있다\
   ③ `ORDER BY`를 적지 않으면 입력한 순서대로 나오는 것이 보장된다\
   ④ 컬럼 번호는 `SELECT` 목록의 자리를 가리킨다

   답. ③. `ORDER BY`가 없으면 결과의 차례는 정해져 있지 않습니다.
2. 아래 문장에서 정렬의 기준이 되는 컬럼은?

   ```sql
   SELECT 사원명, 상여, 급여 FROM 사원 ORDER BY 3;
   ```

   ① 사원명\
   ② 상여\
   ③ 급여\
   ④ 테이블의 셋째 컬럼인 급여

   답. ③. 번호는 `SELECT` 목록의 자리이므로 셋째 자리인 급여입니다. 테이블의 셋째 컬럼도 급여이지만 그것을 따르는 것이 아니라서 ④는 이유가 틀렸습니다.
3. Oracle에서 위 사원 테이블에 `SELECT 사원명 FROM 사원 ORDER BY 상여 DESC`를 실행했을 때 첫 행이 될 수 없는 사람은?\
   ① 김철수\
   ② 박민수\
   ③ 정대현\
   ④ 이영희

   답. ④. Oracle은 NULL을 가장 큰 값으로 보므로 내림차순에서 NULL인 세 사람이 먼저 오고, 그 셋끼리의 차례는 정해져 있지 않습니다. 이영희(100)는 넷째입니다.
4. 위 사원 테이블에서 `ORDER BY 부서코드 DESC, 급여`로 정렬했을 때(Oracle) 둘째 행은?\
   ① 정대현\
   ② 최지은\
   ③ 박민수\
   ④ 홍길동

   답. ②. 부서코드 내림차순에서 NULL이 맨 앞이라 정대현이 첫째, D03의 최지은이 둘째입니다. 급여는 부서코드가 같은 행끼리만 가릅니다.
5. `SELECT` 문의 처리 순서로 옳은 것은?\
   ① `SELECT` → `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `ORDER BY`\
   ② `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`\
   ③ `FROM` → `GROUP BY` → `WHERE` → `HAVING` → `SELECT` → `ORDER BY`\
   ④ `FROM` → `WHERE` → `SELECT` → `GROUP BY` → `HAVING` → `ORDER BY`

   답. ②. ①은 적는 순서입니다.
6. 다음 중 오류가 나는 문장은?\
   ① `SELECT 급여 * 12 AS 연봉 FROM 사원 ORDER BY 연봉`\
   ② `SELECT 급여 * 12 AS 연봉 FROM 사원 WHERE 연봉 > 3000`\
   ③ `SELECT 부서코드, SUM(급여) FROM 사원 GROUP BY 부서코드 ORDER BY SUM(급여)`\
   ④ `SELECT 사원명 FROM 사원 ORDER BY 급여 DESC, 사원명`

   답. ②. `WHERE`는 `SELECT`보다 먼저 처리되어 별칭 연봉이 아직 없습니다. `WHERE 급여 * 12 > 3000`으로 적어야 합니다.
7. Oracle에서 `ORDER BY 상여 DESC NULLS LAST`로 위 사원 테이블을 정렬했을 때 셋째 행의 상여는?\
   ① 100\
   ② 50\
   ③ 30\
   ④ NULL

   답. ③. NULL을 맨 뒤로 보냈으므로 100, 50, 30 다음에 NULL 셋이 옵니다.
8. 정렬 방향에 대한 설명으로 옳은 것은?\
   ① `ORDER BY a, b DESC`는 a와 b 모두 내림차순이다\
   ② `ORDER BY a, b DESC`는 a 오름차순, b 내림차순이다\
   ③ SQL Server는 오름차순에서 NULL을 맨 뒤에 둔다\
   ④ 정렬은 결과 행 수를 줄일 수 있다

   답. ②. 방향은 바로 앞 컬럼에만 걸립니다. SQL Server는 NULL을 가장 작은 값으로 보아 오름차순에서 맨 앞에 두고, 정렬은 행 수를 바꾸지 않습니다.

이로써 한 테이블을 다루는 `SELECT` 문의 절이 모두 모였습니다. 여기서 정리한 처리 순서는 여러 테이블을 잇는 조인과 문장 안에 문장을 넣는 서브쿼리로 가도 그대로이고, 거기서는 `FROM` 자리가 하는 일만 넓어집니다.
