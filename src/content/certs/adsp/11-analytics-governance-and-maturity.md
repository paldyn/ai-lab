[앞 노트](/learn/certs/adsp/10-master-plan-and-task-priority)에서 과제의 우선순위를 매기고 이행 로드맵을 그렸습니다. 그런데 로드맵이 3단계 「확산 및 고도화」까지 가려면 과제를 하나 잘 끝내는 것만으로는 모자랍니다. 분석을 맡을 조직이 있어야 하고, 과제를 고르고 돌리는 절차가 있어야 하고, 사람을 길러야 합니다. 이것을 묶어 부르는 이름이 **분석 거버넌스**이고, 분석을 일회성 프로젝트가 아니라 회사의 상시 기능으로 만들기 위한 관리 체계입니다. 이 노트는 거버넌스의 구성요소를 먼저 펼치고, 조직이 지금 어디에 서 있는지 재는 두 잣대 — 준비도와 성숙도 — 를 본 뒤, 조직 구조와 사람 쪽으로 닫습니다.

## 거버넌스 구성요소

### 다섯 요소

분석 거버넌스 체계는 다섯 요소로 짜여 있습니다.

| 요소 | 영문 | 무엇을 갖추나 |
| --- | --- | --- |
| 조직 | Organization | 분석 기획과 관리를 맡을 조직 |
| 과제 기획·운영 프로세스 | Process | 과제를 발굴하고 실행하고 관리하는 절차 |
| 분석 관련 시스템 | System | 분석에 쓰는 IT 기술과 프로그램 |
| 데이터 | Data | 데이터 거버넌스, 곧 데이터를 표준으로 관리하는 체계 |
| 분석 교육·마인드 육성 | Human Resource | 분석 인력 양성과 분석 문화 |

다섯 가운데 하나를 「예산」이나 「외부 컨설팅」 같은 다른 말로 바꿔 끼운 선택지를 가려낼 수 있어야 합니다. 영문 이름과 우리말 이름을 엇갈려 짝지은 선택지도 마찬가지입니다.

### 과제 관리 프로세스

Process 요소의 속을 들여다보면 두 덩어리입니다. 과제 발굴은 분석 아이디어를 발굴하고, 분석 과제 후보를 제안하고, 분석 과제를 확정하는 세 걸음입니다. 과제 수행은 팀을 구성하고, 분석 과제를 실행하고, 진행을 관리하고, 결과를 공유하고 개선하는 걸음입니다. 끝난 과제의 결과와 경험은 다시 다음 과제 발굴의 자료가 되어, 두 덩어리가 고리처럼 이어집니다. 이렇게 쌓인 결과를 지식으로 남겨 두는 것도 이 프로세스의 몫입니다.

### 데이터 거버넌스

Data 요소는 **데이터 거버넌스**로 따로 부를 만큼 덩치가 큽니다. 데이터 거버넌스는 전사의 데이터를 표준에 따라 관리해 품질과 보안을 지키는 체계로, 원칙·조직·프로세스 셋으로 구성되고 데이터 표준화, 데이터 관리 체계, 데이터 저장소 관리, 표준화 활동을 체계로 둡니다. 데이터 표준화는 용어와 명명 규칙, 메타데이터를 통일하는 일이고, 데이터 관리 체계는 데이터의 생명 주기를 관리하는 절차를 세우는 일입니다. 빅데이터 거버넌스는 여기에 데이터 양이 크고 비정형이 섞인다는 점을 더해, 모든 데이터를 똑같이 관리하기보다 산업과 데이터 성격에 따라 무엇을 우선 관리할지 정합니다.

## 분석 준비도

### 여섯 영역

**분석 준비도**(Readiness)는 조직이 데이터 분석을 도입할 준비가 얼마나 됐는지를 재는 잣대입니다. 여섯 영역으로 나눠 영역마다 항목을 점검합니다.

| 영역 | 점검하는 것의 예 |
| --- | --- |
| 분석 업무 파악 | 발생한 사실 분석, 예측 분석, 최적화 분석 업무가 있는가 |
| 인력 및 조직 | 분석 전문가와 전담 조직, 경영진의 분석 이해 |
| 분석 기법 | 업무별 적합한 기법을 쓰는가, 기법 라이브러리가 있는가 |
| 분석 데이터 | 데이터가 충분하고 신뢰할 만한가, 표준이 있는가 |
| 분석 문화 | 사실에 근거한 의사결정, 데이터 활용 의지 |
| IT 인프라 | 운영 시스템 통합, 분석 전용 환경 |

### 진단 방법

준비도는 영역마다 점수를 매겨 일정 수준을 넘는지 봅니다. 여섯 영역 가운데 하나만 높아서는 준비됐다고 보지 않습니다 — 분석 전문가를 뽑아 놓아도(인력) 데이터가 없거나(분석 데이터) 결과를 의사결정에 쓰지 않으면(분석 문화) 분석은 돌아가지 않기 때문입니다. 영역 이름 여섯을 늘어놓고 하나를 「분석 성과」나 「분석 예산」처럼 바꿔 놓은 선택지가 오답의 꼴입니다. 「분석 문화」가 준비도의 한 영역이라는 점도 함께 붙잡습니다 — 문화는 거버넌스 요소에서도, 준비도 영역에서도 나옵니다.

## 분석 성숙도

### 네 단계

**분석 성숙도**(Maturity)는 조직이 분석을 얼마나 깊이 쓰고 있는지를 재는 잣대입니다. 소프트웨어 개발 조직의 역량을 단계로 재는 CMMI(Capability Maturity Model Integration) 모델을 빌려 와, 도입 → 활용 → 확산 → 최적화 네 단계로 나눕니다.

| 단계 | 한 줄 | 비즈니스 부문 | 조직·역량 부문 | IT 부문 |
| --- | --- | --- | --- | --- |
| 도입 | 분석을 시작해 환경과 시스템을 구축 | 실적 분석과 통계, 정기 보고 | 일부 부서가 수행, 담당자 역량에 의존 | 데이터 웨어하우스, 데이터 마트, ETL·EAI, OLAP |
| 활용 | 분석 결과를 실제 업무에 적용 | 미래 결과 예측, 시뮬레이션 | 전문 담당 부서에서 수행 | 실시간 대시보드, 통계 분석 환경 |
| 확산 | 전사 차원에서 분석을 관리·공유 | 전사 성과 실시간 분석, 분석 규칙 관리 | 전 부서가 수행, 분석 COE 조직 운영 | 빅데이터 관리 환경, 비주얼 분석, 분석 전용 서버 |
| 최적화 | 분석이 혁신과 성과 향상에 기여 | 외부 환경 분석, 최적화 업무 적용, 비즈니스 모델 진화 | 데이터 사이언스 그룹, 경영진이 분석을 활용 | 분석 협업 환경, 분석 샌드박스, 프로세스 내재화 |

**COE**(Center of Excellence)는 분석 역량을 모아 전사를 지원하는 전문 조직입니다. 도입 단계의 IT 항목인 데이터 웨어하우스와 OLAP는 「이미 일어난 일을 모아 본다」는 데서 멈추고, 활용 단계로 가야 예측이 들어옵니다.

### 세 부문

성숙도는 비즈니스, 조직·역량, IT 세 부문으로 나눠 진단합니다. 표의 칸에 든 항목을 보고 어느 단계인지 고르는 꼴로 물을 수 있으므로, 단계마다 핵심 낱말 하나씩을 붙잡아 둡니다 — 도입은 정기 보고, 활용은 예측, 확산은 전사와 COE, 최적화는 외부 환경과 비즈니스 모델 진화입니다. 예를 들어 「분석 샌드박스를 운영한다」는 최적화, 「분석 전용 서버를 둔다」는 확산입니다.

## 준비도와 성숙도 사분면

### 네 유형

두 잣대를 가로세로로 놓으면 조직이 네 유형으로 갈립니다.

| | 성숙도 낮음 | 성숙도 높음 |
| --- | --- | --- |
| 준비도 낮음 | 준비형 | 정착형 |
| 준비도 높음 | 도입형 | 확산형 |

**준비형**은 준비도도 성숙도도 낮아 분석에 필요한 데이터·조직·인력·기법을 사전에 갖추는 것부터 해야 하는 유형입니다. **정착형**은 준비도는 낮지만 조직·인력·기법을 제한적으로나마 이미 쓰고 있어 성숙도가 높은 편인 유형이고, 그 쓰임을 1차로 정착시키는 것이 과제입니다. **도입형**은 지금 분석 업무와 기법은 모자라 성숙도가 낮지만 조직과 인력 등 준비도가 높아 바로 도입할 수 있는 유형입니다. **확산형**은 여섯 영역을 다 갖추고 이미 부분적으로 도입해 지속적으로 확산하는 유형입니다.

### 헷갈리는 둘

가장 엇갈리기 쉬운 것이 정착형과 도입형입니다. 이름만 보면 도입형이 먼저일 것 같지만, 사분면에서 도입형은 「준비는 됐는데 아직 안 쓰는」 칸이고 정착형은 「준비는 덜 됐는데 이미 쓰고 있는」 칸입니다. 준비도를 기준으로 「높으면 도입형·확산형, 낮으면 준비형·정착형」으로 먼저 가르고, 그다음 성숙도로 한 번 더 가르면 됩니다. 상황 문장에서 「인력과 조직은 갖췄지만 분석 업무는 아직 없다」가 보이면 도입형, 「제대로 된 체계는 없지만 일부 부서가 분석을 쓰고 있다」가 보이면 정착형입니다.

## 분석 조직 구조

### 세 구조

분석을 맡을 조직을 어떻게 둘지는 세 구조로 갈립니다.

| 구조 | 어떻게 두나 | 강점 | 약점 |
| --- | --- | --- | --- |
| 집중형 | 별도 분석 전담 조직이 전사 분석을 맡는다 | 전략적 중요도에 따라 우선순위를 정해 추진 | 현업 부서의 분석 업무와 이원화·중복될 수 있다 |
| 기능형 | 별도 조직 없이 각 현업 부서가 직접 분석한다 | 일반적인 형태, 업무에 가까운 분석 | 전사 관점의 핵심 분석이 어렵고 부서의 과거 실적 분석에 머물기 쉽다 |
| 분산형 | 분석 전담 인력을 현업 부서에 배치한다 | 전사 차원의 우선순위로 수행하면서 현업에 빠르게 적용, 베스트 프랙티스 공유 | 부서 분석 업무와 역할 분담을 명확히 해야 한다 |

### 구조 고르기

세 구조를 가르는 질문은 둘입니다. 분석 전담 조직이 따로 있는가, 있다면 분석 인력이 어디에 앉아 있는가입니다. 전담 조직이 없으면 기능형, 있고 인력이 그 조직에 모여 있으면 집중형, 있지만 인력이 현업 부서에 흩어져 앉아 있으면 분산형입니다. 기능형과 분산형은 둘 다 현업 부서에서 분석이 일어난다는 점이 같아서 엇갈리기 쉬운데, 분산형은 전사 조직이 우선순위를 정하고 인력을 내려보낸 것이고 기능형은 그런 전사 조직 자체가 없다는 점이 다릅니다.

## 분석 인력과 분석 문화

### 인력 양성

Human Resource 요소는 사람을 기르는 일입니다. 분석 전문 인력을 뽑고 기르는 것만이 아니라, 경영진에게는 데이터에 근거한 의사결정을 하도록, 현업 담당자에게는 자기 업무에서 분석 기회를 찾도록 교육합니다. 교육의 목표는 분석 도구를 다루는 법보다 분석 역량, 곧 데이터로 무엇을 물어야 하는지를 아는 힘을 기르는 데 있습니다. 「도구 사용법 교육이 분석 교육의 핵심이다」라고 적힌 선택지가 오답입니다.

### 분석 문화

**분석 문화**는 의사결정을 직관이나 관행이 아니라 데이터와 사실에 근거해 내리는 습관이 조직에 자리 잡은 상태입니다. 교육을 한두 번 한다고 생기지 않으므로 변화 관리로 다룹니다 — 분석 결과를 실제 결정에 쓰는 사례를 만들고, 그 성과를 공유해 다음 결정에서도 데이터를 찾게 만드는 것입니다. 성숙도가 도입에서 최적화로 오를수록 분석을 쓰는 사람이 일부 담당자에서 전 부서, 그리고 경영진으로 넓어지는데, 그 넓어지는 과정이 곧 분석 문화가 자리 잡는 과정입니다.

## 연습 문제

1. 분석 거버넌스 체계의 구성요소가 아닌 것은?\
   ① 조직(Organization)\
   ② 과제 기획·운영 프로세스(Process)\
   ③ 분석 예산(Budget)\
   ④ 분석 교육·마인드 육성(Human Resource)

   답. ③. 다섯 요소는 조직, 프로세스, 시스템, 데이터, 분석 교육·마인드 육성입니다.
2. 분석 준비도의 여섯 영역에 들지 않는 것은?\
   ① 분석 업무 파악\
   ② 분석 문화\
   ③ 분석 성과\
   ④ IT 인프라

   답. ③. 나머지 둘은 인력 및 조직, 분석 기법, 분석 데이터입니다.
3. 분석 성숙도 단계를 낮은 것부터 놓은 것은?\
   ① 도입 → 확산 → 활용 → 최적화\
   ② 도입 → 활용 → 확산 → 최적화\
   ③ 활용 → 도입 → 확산 → 최적화\
   ④ 도입 → 활용 → 최적화 → 확산

   답. ②. 시작해 구축하고, 업무에 쓰고, 전사로 넓히고, 혁신에 기여합니다.
4. 분석 COE 조직을 운영하고 분석 전용 서버를 두는 성숙도 단계는?\
   ① 도입\
   ② 활용\
   ③ 확산\
   ④ 최적화

   답. ③. 최적화 단계는 데이터 사이언스 그룹과 분석 샌드박스로 구별됩니다.
