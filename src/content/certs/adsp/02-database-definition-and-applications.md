[앞 노트](/learn/certs/adsp/01-data-information-and-dikw)에서 데이터가 정보와 지식으로 올라가는 층을 세웠습니다. 이번에는 그 데이터가 실제로 어디에 담겨 있는지를 봅니다. ADsP 1과목에서 이 범위는 정의 한두 문항과 「분야와 시스템의 짝이 어긋난 것 고르기」 한 문항으로 나오는 자리이고, 외울 것이 가장 많은 대신 헷갈릴 일은 가장 적습니다. 낱말을 소리로만 익히면 약자가 섞이는 순간 무너지므로, 각 이름이 무엇의 줄임말인지까지 함께 붙잡습니다.

## 데이터베이스

### 네 가지 성질

**데이터베이스**는 여러 사람이 함께 쓰려고 체계적으로 정리해 통합 관리하는 데이터의 묶음입니다. 정의 자체가 네 조각으로 쪼개져 문항이 됩니다.

| 성질 | 무슨 뜻인가 |
| --- | --- |
| 통합된 데이터 | 같은 값을 여러 벌 두지 않고 하나로 모은 것 |
| 저장된 데이터 | 컴퓨터가 접근할 수 있는 매체에 담긴 것 |
| 공용 데이터 | 한 사람이 아니라 여러 사용자가 나눠 쓰는 것 |
| 변화되는 데이터 | 삽입·삭제·갱신으로 내용이 계속 달라지는 것 |

### 다섯 가지 특징

성질과 따로 외우는 목록이 하나 더 있습니다. 데이터베이스가 그렇게 굴러가기 때문에 생기는 특징들입니다.

| 특징 | 무슨 뜻인가 |
| --- | --- |
| 통합성 | 중복을 최소화해 자료의 불일치를 없앤다 |
| 실시간 접근성 | 질의에 곧바로 응답한다 |
| 계속적인 변화 | 갱신이 일어나도 늘 최신 상태를 지킨다 |
| 동시 공용 | 여러 사용자가 같은 데이터를 동시에 쓴다 |
| 내용에 의한 참조 | 저장된 물리적 주소가 아니라 값으로 데이터를 찾는다 |

마지막 항목이 가장 자주 나옵니다. 「내용에 의한 참조」는 파일이 디스크의 몇 번째 자리에 있는지를 몰라도 「나이가 30 이상인 사람」이라고 값의 조건만 말하면 찾아 준다는 뜻입니다. 성질과 특징을 섞어 놓고 고르게 하는 문항도 나오는데, 네 성질은 정의를 쪼갠 것이라 「~된 데이터」로 끝나고 다섯 특징은 굴러가는 모습이라 「~성」이나 「~ 변화」로 끝난다는 어미의 차이로 갈라집니다.

### DBMS와 SQL

데이터베이스가 데이터의 묶음이라면, 그 묶음을 만들고 고치고 꺼내 주는 소프트웨어가 **DBMS**입니다. 사람이 DBMS에 무엇을 달라고 말할 때 쓰는 언어가 **SQL**입니다. 셋의 사이를 한 문장으로 하면, 사용자는 SQL로 요청을 적고 DBMS가 그것을 읽어 데이터베이스에서 값을 꺼내 돌려줍니다. 데이터는 데이터베이스에 있고, DBMS는 그것을 다루는 프로그램이며, SQL은 그 프로그램에 말을 거는 문법이라고 층을 갈라 두면 섞이지 않습니다. 데이터베이스와 DBMS를 같은 것으로 적어 놓은 선택지, 그리고 SQL을 프로그래밍 언어가 아니라 데이터베이스 제품 이름처럼 써 놓은 선택지가 오답으로 나옵니다.

## OLTP와 OLAP

### OLTP

**OLTP**는 주문·결제·예약처럼 그 순간의 거래를 처리하는 시스템입니다. 질의 하나하나는 짧고 모양이 미리 정해져 있으며, 대신 그런 질의가 대량으로 들어옵니다. 값이 어긋나면 안 되므로 중복을 줄이는 쪽으로 테이블을 설계합니다.

### OLAP

**OLAP**은 쌓인 데이터를 여러 각도로 돌려 보며 분석하는 시스템입니다. 「지난 3년 동안 지역별·분기별 매출」처럼 한 번에 넓은 범위를 읽고, 삽입·수정보다 읽기가 압도적으로 많습니다.

| 견주는 자리 | OLTP | OLAP |
| --- | --- | --- |
| 하는 일 | 거래 처리 | 분석과 의사결정 지원 |
| 질의 모양 | 짧고 정형화된 것이 대량으로 | 길고 복잡한 것이 소량으로 |
| 다루는 시점 | 현재 | 현재와 과거를 함께 |
| 주된 연산 | 삽입·수정·삭제 | 읽기 |

### 정규화와 비정규화

둘의 설계가 갈리는 이유는 목적이 다르기 때문입니다. OLTP는 같은 값을 여러 곳에 두면 한쪽만 고쳐지는 사고가 나므로 중복을 쪼개는 정규화를 씁니다. OLAP은 이미 확정된 값을 읽기만 하므로, 조인을 줄여 조회를 빠르게 하려고 일부러 중복을 허용하는 비정규화를 씁니다. 「OLTP가 비정규화를 적극 허용한다」는 선택지는 방향이 뒤집힌 오답입니다.

## 데이터 웨어하우스

### 네 성질

**데이터 웨어하우스**는 여러 업무 시스템에 흩어진 데이터를 분석하기 좋게 모아 둔 저장소입니다. 성질 넷으로 정의합니다. 업무가 아니라 분석 주제를 중심으로 모으므로 주제 지향적이고, 시스템마다 다르던 코드와 단위를 맞추므로 통합적이며, 시점을 붙여 이력을 남기므로 시계열적이고, 한 번 적재한 값을 고치지 않으므로 비휘발적입니다.

마지막 둘이 함께 문항이 됩니다. 운영 시스템에서 고객 주소가 바뀌어도 웨어하우스에는 옛 주소가 그대로 남는데, 시점을 붙여 쌓고 고치지 않기 때문입니다. 운영 시스템은 지금 맞는 값 하나만 들고 있으면 되지만 분석은 「그때는 어땠는가」를 묻기 때문에, 같은 데이터를 두 곳에 다르게 담는 이 차이가 웨어하우스를 따로 세우는 이유이기도 합니다.

### 데이터 마트

**데이터 마트**는 웨어하우스에서 특정 부서나 주제에 필요한 부분만 잘라 낸 작은 저장소입니다. 영업팀은 영업 마트만 보면 되므로 조회가 빠르고 권한 관리가 쉽습니다. 웨어하우스가 전사 단위, 마트가 부서 단위라는 크기의 차이로 기억하면 됩니다. 순서를 뒤집어 「마트를 모아 웨어하우스를 만든다」고 적은 선택지가 나오는데, 전사 저장소를 먼저 세우고 거기서 잘라 내는 쪽이 표준 설명입니다.

### ETL과 EAI

데이터를 웨어하우스로 옮기는 일은 **ETL**이 맡습니다. 원천에서 뽑고(Extract) 형식을 맞추고(Transform) 저장소에 싣는(Load) 세 걸음입니다.

**EAI**는 다른 일을 합니다. 기업 안의 시스템들이 서로 직접 연결되어 실타래처럼 엉키는 것을 막으려고, 가운데에 허브를 두고 모든 연동을 그리로 모으는 방식입니다. ETL은 분석용 저장소를 채우려고 데이터를 옮기는 것이고 EAI는 업무 시스템끼리 계속 주고받게 잇는 것이라, 목적이 다릅니다. 연결의 모양으로도 갈립니다. 시스템이 열 개면 서로 직접 잇는 선이 마흔다섯 개까지 늘어나 하나를 고칠 때마다 나머지를 다 건드려야 하는데, 허브를 가운데 두면 선이 열 개로 줄고 새 시스템은 허브에만 붙이면 됩니다. 이것이 EAI를 쓰는 이유이고, ETL에는 그런 상시 연결이라는 개념 자체가 없습니다.

## 기업 안의 시스템

### CRM

**CRM**은 고객 접점에서 생기는 데이터로 고객을 이해하고 관계를 관리하는 시스템입니다. 구매 이력, 상담 기록, 문의 내역처럼 개별 고객 단위로 데이터가 쌓입니다.

### SCM

**SCM**은 조달·생산·유통·납품에 이르는 공급 사슬 전체를 관리하는 시스템입니다. 재고 수량, 리드타임, 운송 상태처럼 품목과 거점 단위로 데이터가 쌓입니다. CRM이 회사 바깥의 고객을 보고 SCM이 회사 안팎의 물건 흐름을 본다는 점에서 갈립니다.

### ERP

**ERP**는 인사·회계·구매·생산처럼 회사의 자원을 한 시스템 안에서 통합해 관리하는 것입니다. CRM과 SCM이 특정 영역을 깊게 보는 시스템이라면 ERP는 회사 전체를 한 판에 올리는 시스템입니다.

## 분야별 데이터베이스

### 제조·금융·유통

제조 부문은 생산 설비에서 나오는 값으로 품질을 관리하고, 앞의 SCM과 ERP가 이 부문에서 널리 쓰입니다. 금융 부문은 거래 기록을 바탕으로 신용 평가와 부정 거래 탐지에 쓰며, 값이 하나만 어긋나도 사고가 되므로 앞에서 본 OLTP 성격이 가장 강한 자리입니다. 유통 부문은 판매 시점의 기록과 **RFID** 같은 전자 태그로 재고와 물건의 위치를 좇습니다. 세 부문이 같은 문항에 함께 나올 때는 「무엇을 세는가」로 갈라집니다 — 제조는 설비와 공정, 금융은 거래, 유통은 물건과 판매 시점입니다.

### 물류·지리·교통

| 부문 | 이름 | 무엇인가 |
| --- | --- | --- |
| 물류 | CVO | 화물 차량의 위치와 운행을 관리하는 첨단화물운송 시스템 |
| 지리 | GIS | 위치에 값을 붙여 지도 위에서 다루는 지리정보 시스템 |
| 교통 | ITS | 도로와 차량에 정보 기술을 붙인 지능형교통 시스템 |

### 의료·교육

| 부문 | 이름 | 무엇인가 |
| --- | --- | --- |
| 의료 | HIS | 진료·처방·수납을 다루는 병원정보 시스템 |
| 의료 | PACS | 영상 촬영 결과를 저장하고 전송하는 시스템 |
| 교육 | NEIS | 학사와 교무를 다루는 교육행정정보 시스템 |

문항은 대개 짝을 하나만 어긋나게 해 놓고 고르게 합니다. 특히 NEIS를 의료 쪽에 붙여 놓는 선택지가 흔하므로, 이름의 첫 글자가 무엇의 줄임말인지까지 읽어 두면 그 자리에서 걸러집니다. GIS는 지리, ITS는 교통, HIS는 병원, NEIS는 교육이라는 식으로 머리글자 하나만 붙잡아도 넷 중 셋은 그 자리에서 갈립니다.

## 연습 문제

1. 데이터베이스의 특징 중 「내용에 의한 참조」를 바르게 설명한 것은?\
   ① 여러 사용자가 동시에 같은 데이터를 쓸 수 있다\
   ② 저장된 물리적 주소가 아니라 값으로 데이터를 찾는다\
   ③ 갱신이 일어나도 항상 최신 상태를 유지한다\
   ④ 질의에 곧바로 응답한다

   답. ②. ①은 동시 공용, ③은 계속적인 변화, ④는 실시간 접근성입니다.
2. OLTP와 OLAP을 견준 것으로 옳지 않은 것은?\
   ① OLTP는 짧고 정해진 질의가 대량으로 들어온다\
   ② OLAP은 현재와 과거 데이터를 함께 다룬다\
   ③ OLTP는 조회 속도를 위해 비정규화를 적극 허용한다\
   ④ OLAP은 삽입·수정보다 읽기가 압도적으로 많다

   답. ③. 방향이 뒤집혔습니다. 비정규화를 허용하는 쪽은 OLAP이고, OLTP는 값이 어긋나지 않도록 정규화합니다.
3. 데이터 웨어하우스의 네 성질 가운데, 운영 시스템에서 고객 주소가 바뀌어도 옛 주소가 그대로 남는 이유에 해당하는 것은?\
   ① 주제 지향적\
   ② 통합적\
   ③ 시계열적이고 비휘발적\
   ④ 실시간 접근성

   답. ③. 시점을 붙여 이력을 남기고(시계열적) 적재한 값을 고치지 않기(비휘발적) 때문입니다. ④는 데이터베이스 일반의 특징이라 웨어하우스의 네 성질에 들어가지 않습니다.
4. ETL과 EAI에 대한 설명으로 옳은 것은?\
   ① ETL은 시스템끼리 허브를 통해 연동하게 잇는 방식이다\
   ② EAI의 T는 형식을 맞추는 변환 단계를 뜻한다\
   ③ ETL은 원천에서 뽑아 변환한 뒤 저장소에 싣는 세 걸음이다\
   ④ 둘은 이름만 다를 뿐 같은 일을 한다

   답. ③. ①은 EAI의 설명이고, ②의 EAI는 Enterprise Application Integration이라 변환 단계와 무관합니다. ④는 목적이 달라 틀렸습니다 — ETL은 분석용 저장소를 채우고 EAI는 업무 시스템을 잇습니다.
5. 분야와 시스템의 짝으로 옳지 않은 것은?\
   ① 물류 — CVO\
   ② 지리 — GIS\
   ③ 의료 — NEIS\
   ④ 유통 — RFID

   답. ③. NEIS는 교육행정정보 시스템으로 교육 부문입니다. 의료 쪽은 HIS와 PACS입니다.
6. CRM, SCM, ERP에 대한 설명으로 옳지 않은 것은?\
   ① CRM에는 구매 이력과 상담 기록이 고객 단위로 쌓인다\
   ② SCM은 조달에서 납품까지의 공급 사슬을 다룬다\
   ③ ERP는 인사·회계·구매·생산을 한 시스템에서 통합 관리한다\
   ④ SCM은 고객 접점에서 생기는 데이터를 분석해 관계를 관리한다

   답. ④. 고객 접점 데이터를 다루는 것은 CRM입니다. SCM에는 재고 수량과 리드타임처럼 품목·거점 단위의 값이 쌓입니다.
