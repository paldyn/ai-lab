이미지와 글을 같은 공간에 놓는 모델의 학습 루프는 뜻밖에 짧습니다.

```python
logits = (img_emb @ txt_emb.T) / temperature      # N × N 점수 행렬
labels = torch.arange(N)                          # 정답은 대각선
loss = (ce(logits, labels) + ce(logits.T, labels)) / 2
```

배치 안의 이미지 $$N$$ 개와 글 $$N$$ 개로 점수 행렬을 만들고, **각 행에서 자기 짝을 골라내는 분류 문제**를 풉니다. 이런 학습을 **대조학습**(contrastive learning)이라 하고, 이 손실을 **InfoNCE**라 부릅니다.

이 방식에는 널리 알려진 경험칙이 하나 붙어 있습니다. **배치가 클수록 잘 된다.** 큰 모델들이 배치를 3만 개씩 쓰는 이유이기도 합니다. 그런데 왜 그런지는 「음성 표본이 많아서」쯤에서 멈추는 일이 많습니다.

이 글에서 저 한 줄이 실제로 최대화하는 양을 정의하고, 배치 크기가 그 양의 **천장**을 정한다는 것을 유도합니다. [지난 글](/articles/math-kl-divergence)의 KL 발산이 그대로 다시 나옵니다.

## 조건부 엔트로피 — 답을 알고 난 뒤에 남는 놀람

먼저 도구 하나가 필요합니다. 두 확률변수 $$X$$, $$Y$$ 를 함께 다루는 분포를 **결합분포** $$p(x,y)$$ 라 하고, 한쪽만 남기고 더한 것을 **주변분포** $$p(x) = \sum_y p(x,y)$$ 라 합니다.

$$Y$$ 의 값을 알고 난 뒤에도 $$X$$ 에 남아 있는 불확실성을 재고 싶습니다. $$Y = y$$ 라는 것을 알았을 때의 엔트로피는 $$H(X \mid Y = y)$$ 이고, 이것을 $$y$$ 에 대해 평균 냅니다.

> **정의.** **조건부 엔트로피**는
> $$H(X \mid Y) = \sum_y p(y)\, H(X \mid Y = y) = -\sum_{x,y} p(x,y) \log p(x \mid y)$$
> 이다.

**$$H(X)$$ 와 다른 곳은 로그 안쪽뿐**입니다. $$p(x)$$ 대신 $$p(x \mid y)$$ 를 쓰니 「$$y$$ 를 알고 나서의 놀람」이 되고, 바깥의 $$p(x,y)$$ 가 그것을 평균 냅니다.

## 상호정보량 — 줄어든 놀람의 양

$$Y$$ 를 알고 나서 $$X$$ 의 불확실성이 얼마나 줄었는가. 그 차이가 두 변수가 공유하는 정보의 양입니다.

> **정의.** **상호정보량**(mutual information)은
> $$I(X; Y) = H(X) - H(X \mid Y)$$
> 이다.

![엔트로피들이 겹치는 자리가 상호정보량이다](/assets/posts/math-mutual-information-venn.svg)

같은 양을 적는 방법이 셋입니다. 정의를 펼쳐 보면 셋이 하나로 모입니다.

$$I(X;Y) = -\sum_{x} p(x) \log p(x) + \sum_{x,y} p(x,y) \log p(x \mid y)$$

첫 항의 $$p(x)$$ 를 $$\sum_y p(x,y)$$ 로 바꿔 두 항의 바깥을 맞추고, $$p(x \mid y) = p(x,y)/p(y)$$ 를 넣으면

$$I(X;Y) = \sum_{x,y} p(x,y) \log \frac{p(x,y)}{p(x)\,p(y)}$$

가 나옵니다. **이 식은 $$x$$ 와 $$y$$ 를 바꿔도 그대로**이므로 $$I(X;Y) = I(Y;X) = H(Y) - H(Y\mid X)$$ 입니다. 그리고 오른쪽을 자세히 보면 지난 글의 그 식입니다.

$$I(X;Y) = D_{\mathrm{KL}}\big(p(x,y) \,\big\|\, p(x)p(y)\big)$$

**상호정보량은 결합분포와 «독립이었다면 그랬을 분포» 사이의 KL 발산**입니다. 이 한 줄에서 성질 셋이 공짜로 따라옵니다.

- $$I(X;Y) \ge 0$$ — KL 발산이 음수가 될 수 없기 때문입니다.
- **$$I = 0$$ 인 것과 $$X$$, $$Y$$ 가 독립인 것이 같은 말**입니다. KL의 등호 조건이 $$p(x,y) = p(x)p(y)$$ 이기 때문입니다.
- **대칭입니다.** KL 자체는 대칭이 아니지만, 여기서는 두 인자에 넣는 것이 $$x$$ 와 $$y$$ 를 바꿔도 같은 짝이라 결과가 대칭이 됩니다.

## 손으로 세어 보기

$$X$$ 와 $$Y$$ 가 각각 값을 둘씩 갖는 표로 확인합니다.

| $$p(x,y)$$ | $$Y=1$$ | $$Y=2$$ | $$p(x)$$ |
| --- | --- | --- | --- |
| $$X=A$$ | 0.4 | 0.1 | 0.5 |
| $$X=B$$ | 0.1 | 0.4 | 0.5 |
| $$p(y)$$ | 0.5 | 0.5 | |

주변분포가 둘 다 반반이므로 $$H(X) = H(Y) = 1$$ 비트입니다. 결합 엔트로피는

$$H(X,Y) = -2\big(0.4 \log_2 0.4\big) - 2\big(0.1 \log_2 0.1\big) = 1.0575 + 0.6644 = 1.7219 \text{ 비트}$$

이고, $$H(X \mid Y) = H(X,Y) - H(Y) = 0.7219$$ 이므로

$$I(X;Y) = 1 - 0.7219 = 0.2781 \text{ 비트}$$

입니다. KL 쪽으로도 세어 봅니다. 독립이었다면 네 칸이 모두 $$0.5 \times 0.5 = 0.25$$ 였을 것입니다.

$$I = 2\left(0.4 \log_2 \frac{0.4}{0.25}\right) + 2\left(0.1 \log_2 \frac{0.1}{0.25}\right) = 0.5425 - 0.2644 = 0.2781$$

![실제 결합분포와 독립이었을 때의 표를 맞대면 그 차이가 상호정보량이다](/assets/posts/math-mutual-information-joint-table.svg)

같은 수입니다. **$$Y$$ 를 알면 $$X$$ 에 대한 놀람이 1비트에서 0.72비트로, 0.28비트만큼 줄어듭니다.** 완전히 알려 주지도 않고 전혀 무관하지도 않은 관계가 이런 숫자로 적힙니다.

## 표본만으로는 재기 어렵다

정의는 깔끔한데 실제로 재려고 하면 벽에 부딪힙니다. 위의 계산에서 우리가 쓴 것은 $$p(x,y)$$ 의 **네 칸 값 전부**였습니다. 표가 있으니 셀 수 있었던 것입니다.

임베딩 512차원짜리 이미지와 글의 결합분포에는 그런 표가 없습니다. 가진 것은 짝지어진 표본 몇 백만 개뿐이고, $$p(x,y)$$ 도 $$p(x)p(y)$$ 도 모릅니다.

칸을 나눠 세는 방법이 왜 안 되는지는 한 줄로 보입니다. 축 하나를 10칸으로만 쪼개도 512차원의 칸 수는 $$10^{512}$$ 개이고, 두 변수를 함께 놓으면 $$10^{1024}$$ 개입니다. 표본을 우주의 원자 수만큼 모아도 **칸 하나에 표본이 하나 들어갈 일이 없습니다.** 상호정보량이 결합분포와 주변분포의 곱을 **비교하는** 양이라 이 문제가 특히 아픕니다 — 둘 다 필요한데 둘 다 모릅니다.

그래서 **재는 대신 아래에서 받치는 값을 만듭니다.** [젠센 부등식 글](/articles/math-jensen-inequality)에서 세운 발상 그대로입니다 — 구할 수 없는 값은 하한으로 바꿔 최대화합니다.

## InfoNCE — 대조 손실이 곧 하한이다

배치에 짝 $$N$$ 개가 있습니다. $$(x_1,y_1), \dots, (x_N, y_N)$$ 이 결합분포에서 나온 진짜 짝이고, 서로 어긋난 $$N^2 - N$$ 개는 가짜 짝입니다. 두 입력에 점수를 매기는 함수 $$f(x,y)$$ 를 하나 두고 — 코드에서는 두 임베딩의 내적을 온도로 나눈 값이었습니다 — 각 행에서 진짜 짝을 골라내는 분류 문제를 풉니다.

> **정의.** **InfoNCE 손실**은
> $$\mathcal{L}_N = -\,\mathbb{E}\left[\log \frac{e^{f(x_i,\, y_i)}}{\sum_{j=1}^{N} e^{f(x_i,\, y_j)}}\right]$$
> 이다.

![행마다 대각선을 정답으로 두는 N개짜리 분류 문제다](/assets/posts/math-mutual-information-infonce-matrix.svg)

**모양이 낯익습니다.** [softmax 유도 글](/articles/math-softmax-derivation)의 그 함수를 한 행의 점수 $$N$$ 개에 씌우고, 정답 자리 하나에 $$-\log$$ 를 취한 값 — 클래스가 $$N$$ 개인 교차엔트로피입니다. 실제로 코드가 `ce(logits, arange(N))` 한 줄인 이유가 이것입니다.

이 손실과 상호정보량이 부등호로 이어집니다.

> **InfoNCE 하한.** $$I(X;Y) \;\ge\; \log N - \mathcal{L}_N$$

유도의 뼈대만 봅니다. 점수함수가 최선으로 학습되면 그것이 재는 것은 **밀도비**

$$r(x,y) = \frac{p(x,y)}{p(x)p(y)}$$

입니다. 이 값의 로그를 진짜 짝에 대해 평균 낸 것이 정확히 $$I(X;Y)$$ 이고요. 최선의 점수함수를 손실에 넣으면 분모에 진짜 짝의 비 하나와 가짜 짝의 비 $$N-1$$ 개가 들어가는데, **가짜 짝은 $$x$$ 와 $$y$$ 를 따로 뽑은 것이라 그 비의 기댓값이 정확히 1**입니다.

$$\mathbb{E}_{y \sim p(y)}\big[r(x,y)\big] = \sum_y p(y) \frac{p(x,y)}{p(x)p(y)} = \sum_y \frac{p(x,y)}{p(x)} = 1$$

그래서 분모가 대략 $$r(x_i,y_i) + (N-1)$$ 이 되고, 로그를 쪼개면 $$-\log r$$ 쪽이 $$-I$$ 를, 나머지가 $$\log N$$ 쪽을 만듭니다. 젠센 부등식이 그 어림을 부등호로 굳혀 줍니다.

처음 코드에서 손실을 두 번 계산해 평균 낸 것도 여기서 읽힙니다. 위 정의는 **행 방향으로만** 뽑았습니다 — 이미지 하나에 글 $$N$$ 개를 댄 것이고, 그러면 $$y$$ 쪽 가짜 짝만 벌을 받습니다. `ce(logits.T, labels)`는 같은 행렬을 열 방향으로 다시 읽어 글 하나에 이미지 $$N$$ 개를 대는 문제로 만든 것입니다. 상호정보량은 대칭인데 InfoNCE 손실은 대칭이 아니므로, **양쪽으로 재서 평균 내는 것**이 자연스러운 선택이 됩니다.

## 천장이 log N이다

부등식을 다시 봅니다. 손실 $$\mathcal{L}_N$$ 은 교차엔트로피이므로 **0보다 작아질 수 없습니다.** 따라서

$$\log N - \mathcal{L}_N \;\le\; \log N$$

입니다. **점수함수가 아무리 완벽해도 이 하한이 증언할 수 있는 값은 $$\log N$$ 을 넘지 못합니다.** 반대쪽 끝도 읽힙니다 — 점수함수가 아무것도 모르면 각 행에서 $$N$$ 개를 고르게 찍으므로 $$\mathcal{L}_N = \log N$$ 이고 하한은 0이 됩니다. 하한이 움직일 수 있는 범위 전체가 $$[0, \log N]$$ 입니다.

![배치 크기가 하한의 천장을 정한다](/assets/posts/math-mutual-information-ceiling.svg)

숫자로 옮기면 경험칙의 정체가 드러납니다.

| 배치 크기 $$N$$ | $$\log N$$ (내트) | 천장 (비트) |
| ---: | ---: | ---: |
| 256 | 5.55 | 8 |
| 1,024 | 6.93 | 10 |
| 4,096 | 8.32 | 12 |
| 32,768 | 10.40 | 15 |

**배치를 두 배로 늘리면 천장이 정확히 1비트 오릅니다.** 로그라서 그렇습니다. 배치 256에서 학습하는 모델은 이미지와 글이 아무리 강하게 얽혀 있어도 8비트어치까지만 목적식으로 밀어붙일 수 있고, 그 위로는 손실이 더 내려갈 자리가 없어 신호가 사라집니다. 「배치가 클수록 잘 된다」는 관찰의 절반이 여기서 설명됩니다.

한 가지 덧붙여 둘 것이 있습니다. **이 천장은 InfoNCE만의 사정이 아닙니다.** 표본 $$N$$ 개만 보고 상호정보량을 아래에서 받치는 어떤 방법도 $$\log N$$ 을 넘게 증언할 수 없다는 것이 알려져 있습니다. 큰 상호정보량을 «재는» 일 자체가 표본 수에 묶여 있는 문제라는 뜻이라, 배치를 키우는 것은 요령이 아니라 **정보를 더 사 오는 일**에 가깝습니다.

## 코드로 확인하기

```python
import numpy as np

# ① 정의 세 가지가 같은 수를 준다
P = np.array([[0.4, 0.1],
              [0.1, 0.4]])                  # 결합분포
px, py = P.sum(1), P.sum(0)                 # 주변분포
H = lambda v: float(-(v[v > 0] * np.log2(v[v > 0])).sum())
print(round(H(px) + H(py) - H(P.ravel()), 4))              # 0.2781
print(round(H(px) - (H(P.ravel()) - H(py)), 4))            # 0.2781
print(round(float((P * np.log2(P / np.outer(px, py))).sum()), 4))   # 0.2781

# ② 독립이면 0
Q = np.outer(px, py)
print(round(float((Q * np.log2(Q / np.outer(px, py))).sum()), 4))   # 0.0

# ③ 완벽한 점수함수라도 하한은 log N에서 막힌다
for N in [256, 1024, 4096, 32768]:
    print(N, round(np.log(N), 2), round(np.log2(N), 2))
# 256 5.55 8.0 / 1024 6.93 10.0 / 4096 8.32 12.0 / 32768 10.4 15.0

# ④ 배치를 두 배로 하면 천장이 정확히 1비트 오른다
print(round(np.log2(2 * 4096) - np.log2(4096), 4))         # 1.0
```

## 정리

- **조건부 엔트로피 $$H(X \mid Y)$$** 는 $$Y$$ 를 알고 난 뒤에 $$X$$ 에 남는 놀람의 평균이다. 엔트로피에서 로그 안쪽만 $$p(x \mid y)$$ 로 바뀐다.
- **상호정보량은 그 줄어든 양** $$I(X;Y) = H(X) - H(X \mid Y)$$ 이고, $$H(Y) - H(Y \mid X)$$ 와도 같아 대칭이다.
- **$$I(X;Y) = D_{\mathrm{KL}}(p(x,y) \| p(x)p(y))$$** 다. 비음수성과 「0이면 독립」이 KL의 성질에서 그대로 따라온다.
- **고차원에서는 표본만으로 잴 수 없다.** 결합분포의 표가 없기 때문이고, 그래서 하한을 만들어 대신 최대화한다.
- **InfoNCE 손실은 $$N$$ 개짜리 교차엔트로피**이고, 코드에서는 점수 행렬의 대각선을 정답으로 두는 한 줄이다.
- **$$I(X;Y) \ge \log N - \mathcal{L}_N$$** 이며, 손실이 0 아래로 못 가므로 하한의 천장이 $$\log N$$ 이다.
- **배치를 두 배로 늘려야 천장이 1비트 오른다.** 그리고 이 천장은 표본 $$N$$ 개로 하한을 만드는 모든 방법에 걸린다.

`loss = ce(logits, arange(N))` 한 줄로 돌아갑니다. 저 줄은 이제 「배치 안에서 짝을 맞히는 분류」가 아니라 **이미지와 글이 공유하는 정보량의 하한을 밀어 올리는 일**로 읽힙니다. 그리고 하한인 이상 천장이 있고, 그 천장을 정하는 손잡이가 배치 크기입니다.

5단원이 여기서 닫힙니다. 정보량 $$-\log p$$ 하나에서 시작해 엔트로피, 교차엔트로피, KL 발산, 상호정보량까지 왔고, 사전학습 손실·라벨 스무딩·RLHF 페널티·증류 손실·대조 손실이 전부 같은 틀에서 나온 값이라는 것을 확인했습니다. **무엇을 최소화하는가**에 대한 답은 여기까지입니다.

다음 단원은 **어떻게 최소화하는가**로 갑니다. 손실이 정해졌으니 이제 그 값을 내리는 방향을 찾아야 하고, 그 방향은 미분이 알려 줍니다.
