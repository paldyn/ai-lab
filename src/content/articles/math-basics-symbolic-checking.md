초급 트랙의 마지막 글입니다. 새 수학은 없고, 앞의 47편을 채점하는 도구를 만듭니다.

[3번 · 손으로 푸는 습관](/articles/math-basics-working-by-hand)에서 검산 셋을 세웠습니다 — 숫자 넣기, 극단값 보기, 두 방법으로 세기. 그 셋을 그대로 코드로 옮기는 것이 이 글이고, 새로 배우는 것은 도구 사용법뿐입니다.

![3번의 검산 셋이 이 글의 도구 셋으로 그대로 옮겨지는 대응](/assets/posts/math-basics-symbolic-checking-three-checks.svg)

채점하는 길은 둘입니다. **기호 계산**은 식 자체를 견주고, **수치 검산**은 값을 견줍니다. 기호로 되면 기호가 확실하고, 안 되면 수치로 갑니다.

먼저 순서를 하나 못 박아 둡니다. 손으로 먼저 풀고, 그다음에 기계로 채점합니다. 기계가 낸 답을 보고 손 풀이를 거기에 맞춰 고치는 것은 채점이 아니라 베끼기입니다. 손 풀이가 어디서 틀렸는지 모르는 채로 답만 맞추면 다음에 같은 자리에서 또 틀립니다. 이 글의 도구는 전부 "내 답이 맞았나"를 묻는 데 쓰고, "답이 뭔가"를 묻는 데는 쓰지 않습니다.

## 기호 계산

### SymPy와 simplify

**SymPy**는 수를 계산하는 대신 식을 기호 그대로 다루는 파이썬 도구입니다. 먼저 문자를 만들어야 식을 적을 수 있습니다.

```python
import sympy as sp

x = sp.symbols('x')
sp.diff(x**2 * sp.sin(x), x)     # 2*x*sin(x) + x**2*cos(x)
```

$$x^2 \sin x$$ 를 미분한 결과입니다. [32번 · 도함수 계산 규칙](/articles/math-basics-derivative-rules)의 곱의 법칙으로 손으로 얻은 것과 같습니다.

그런데 눈으로 견주는 것은 믿을 수 없습니다. 같은 식도 적는 방법이 여럿이라 글자가 달라 보일 수 있습니다. 항의 순서가 바뀌기도 하고, 묶여 있던 것이 풀려 나오기도 합니다. 그래서 두 식을 빼서 0인지 봅니다.

```python
mine = 2*x*sp.sin(x) + x**2*sp.cos(x)          # 손으로 구한 답
sp.simplify(sp.diff(x**2*sp.sin(x), x) - mine) == 0    # True
```

`simplify`는 식을 최대한 정리하는 명령입니다. 차가 0으로 정리되면 두 식은 같습니다. 이것이 기호 검산의 **관용구**, 곧 늘 같은 꼴로 되풀이해 쓰는 한 줄이고, 아래 도구들과 늘 짝을 이룹니다.

### 명령 일곱

| 명령 | 하는 일 | 되짚는 글 |
| --- | --- | --- |
| `sp.diff(f, x)` | 미분 | [32번](/articles/math-basics-derivative-rules) |
| `sp.integrate(f, (x, a, b))` | 정적분 | [34번](/articles/math-basics-fundamental-theorem-of-calculus) |
| `sp.series(f, x, 0, n)` | 테일러 전개 | [35번](/articles/math-basics-taylor-first-steps) |
| `sp.summation(f, (k, a, b))` | 급수의 합 | [29번](/articles/math-basics-geometric-series) |
| `sp.solve(식, x)` | 방정식 풀기 | 16·23번 |
| `sp.expand` · `sp.factor` | 전개·인수분해 | 15번 |
| `sp.limit(f, x, a)` | 극한 | 28번 |

앞의 글들을 그대로 채점해 봅니다.

```python
k = sp.symbols('k')
sp.integrate(x*sp.exp(x), (x, 0, 1))               # 1
sp.series(sp.exp(x), x, 0, 4)                      # 1 + x + x**2/2 + x**3/6 + O(x**4)
sp.summation(sp.Rational(1, 2)**k, (k, 0, sp.oo))  # 2
sp.factor(x**2 - 5*x + 6)                          # (x - 3)*(x - 2)
```

셋째 줄이 [29번](/articles/math-basics-geometric-series)의 첫째항 1, 공비 $$\tfrac12$$ 인 무한등비급수이고, 손으로 얻은 $$\dfrac{1}{1 - 1/2} = 2$$ 와 같습니다. 둘째 줄의 `O(x**4)` 는 47번에서 세운 차수 기호 그대로입니다 — 넷째 차수부터는 잘라 냈다는 표시입니다.

### 구조 비교

관용구가 왜 빼기를 거치는지는 `==` 를 직접 써 보면 알 수 있습니다.

```python
x*(x + 1) == x**2 + x                 # False
sp.expand(x*(x + 1)) == x**2 + x      # True
sp.simplify(x*(x + 1) - (x**2 + x))   # 0
```

[15번](/articles/math-basics-expanding-and-factoring)에서 보았듯 $$x(x+1)$$ 과 $$x^2 + x$$ 는 같은 식입니다. 그런데 첫 줄은 `False` 입니다. SymPy의 `==` 는 두 식이 수학적으로 같은지를 묻지 않고, 적힌 모양이 글자 그대로 같은지를 묻기 때문입니다. 이렇게 모양만 견주는 것을 **구조 비교**라고 합니다. 한쪽은 곱셈 하나, 다른 쪽은 덧셈 하나로 적혀 있으니 구조가 다릅니다.

둘째 줄처럼 한쪽을 전개해 모양을 맞추면 `True` 가 나오지만, 어느 쪽을 어떻게 바꿔야 모양이 맞는지는 식마다 다릅니다. 빼서 정리하는 셋째 줄은 그 고민을 없앱니다. 같은 식끼리의 차는 어떻게 적혀 있든 정리하면 0이 되기 때문입니다. `simplify` 를 거쳐 0과 견주는 까닭이 여기 있습니다.

기호 대조가 `True` 를 냈어도 값으로 한 번 더 확인해 두면 든든합니다. `subs` 는 식의 문자에 수를 넣는 명령입니다.

```python
diff = sp.diff(x**2*sp.sin(x), x) - mine
[diff.subs(x, v) for v in (0, 1, 2)]    # [0, 0, 0]
```

차에 $$x = 0, 1, 2$$ 를 넣어 모두 0이 나왔습니다. 기호로 한 번, 값으로 한 번 — 길이 다른 두 확인이 같은 말을 하면 3번의 "두 방법으로 세기"가 됩니다.

### 정확한 분수

기호 계산에서 가장 조용히 일을 망치는 것이 소수입니다. 파이썬에 `0.1` 이라고 적으면 기계는 그것을 **부동소수점 수**, 곧 유효숫자 약 16자리에서 잘라 담은 근삿값으로 받습니다. [47번](/articles/math-basics-orders-of-magnitude-and-error)의 "자리가 유한하면 자른다, 자른 만큼이 오차다"가 그대로 일어나는 자리입니다.

```python
0.1 + 0.2                                           # 0.30000000000000004
sp.simplify(sp.Rational(3, 10)*x - (0.1 + 0.2)*x)   # -5.55111512312578e-17*x
```

`sp.Rational(3, 10)` 은 분수 $$\tfrac{3}{10}$$ 을 자르지 않고 정확히 담습니다. $$\tfrac{3}{10}x$$ 와 $$(0.1 + 0.2)x$$ 는 손으로는 같은 식인데, 소수 쪽이 잘린 자리를 품고 있어 차가 0이 아니라 $$-5.55 \times 10^{-17}x$$ 로 남습니다. 이 결과를 보고 "손 풀이가 틀렸다"고 결론 내리면 엉뚱한 곳을 뒤지게 됩니다.

그래서 기호 검산에서는 분수를 `sp.Rational` 로, 정수끼리의 나눗셈을 `x/3` 처럼 문자와 함께 적습니다. 차에 $$10^{-17}$$ 같은 아주 작은 수가 남았으면 식이 틀렸다기보다 어디선가 소수가 섞였다고 먼저 의심합니다.

## 의심의 순서

### 네 걸음

대조가 `False` 를 뱉었을 때 아무 데나 뒤지면 오래 걸립니다. 자주 틀리는 자리부터 봅니다.

![부호·속미분·괄호·정의역 순으로 의심하는 네 걸음](/assets/posts/math-basics-symbolic-checking-suspect-order.svg)

1. 부호. 가장 흔합니다. 빼기를 옮기다 하나 놓치거나, $$\cos$$ 을 미분하고 마이너스를 안 붙인 자리입니다.
2. 연쇄법칙의 속미분. $$\sin(3x)$$ 를 미분하고 $$\cos(3x)$$ 라고 적으면 안쪽 $$3x$$ 를 미분한 3이 빠진 것입니다. 옳은 답은 $$3\cos(3x)$$ 입니다.
3. 괄호. 종이에서는 보이던 묶음이 한 줄로 적히며 풀립니다. $$1/(2x)$$ 를 `1/2*x` 로 적으면 다른 식입니다.
4. 정의역 조건. 여기까지 와도 안 맞으면 두 식이 어떤 $$x$$ 에서 같은가를 봅니다. $$\dfrac{x}{x}$$ 와 $$1$$ 은 $$x = 0$$ 을 빼면 같습니다. `simplify` 는 이런 자리를 조용히 지나가므로, 기호 대조가 True 여도 정의역까지 같다는 뜻은 아닙니다.

순서가 이렇게 선 데는 까닭이 있습니다. 앞쪽일수록 자주 나오고, 찾기도 쉽습니다. 부호는 한 글자라 눈으로 금방 확인되고, 속미분은 연쇄법칙을 쓴 자리만 보면 되며, 괄호는 코드로 옮긴 줄만 보면 됩니다. 정의역은 식 전체를 다시 생각해야 해서 가장 비쌉니다. 3번의 의심하는 순서(부호 → 이항 → 괄호)와 뼈대가 같고, 미분이 들어오면서 속미분이 끼어든 것입니다.

### 무작위 대입

`simplify` 가 늘 0까지 정리해 주지는 않습니다. 정리를 하다 말고 식을 남기면, 그 식이 사실 0인지 아닌지를 기호만으로는 판단하기 어렵습니다. 그때 다섯째 걸음으로 무작위 수를 여러 개 넣어 봅니다. 이것을 **무작위 대입**이라고 합니다.

```python
import random

d = sp.simplify(sp.sqrt(x**2) - x)    # -x + sqrt(x**2)  ← 0으로 안 줄었다
random.seed(1)
for _ in range(5):
    v = random.uniform(-3, 3)
    print(round(v, 3), d.subs(x, v))
# -2.194 4.38762907065118
#  2.085 0
#  1.583 0
#  -1.47 2.93917169112694
# -0.027 0.0547789548967081
```

$$\sqrt{x^2}$$ 와 $$x$$ 의 차가 남았습니다. 수를 넣어 보니 양수에서는 0, 음수에서는 0이 아닙니다. 음수 $$-2.194$$ 를 넣으면 $$\sqrt{x^2}$$ 은 $$2.194$$ 이고 거기서 $$-2.194$$ 를 빼니 $$4.388$$ 입니다. [10번](/articles/math-basics-numbers-and-number-line)의 절댓값 그대로, $$\sqrt{x^2} = |x|$$ 이지 $$x$$ 가 아닙니다. `simplify` 가 정리를 멈춘 것은 게을러서가 아니라 정말로 같지 않았기 때문입니다.

무작위 수를 고르는 범위에는 음수와 0 근처를 꼭 넣습니다. 0부터 1 사이만 고르면 위 예의 차이는 영영 안 보입니다. 넷째 걸음의 정의역 의심이 수로 옮겨진 자리입니다.

### 검산의 사각지대

검산이 아무리 꼼꼼해도 못 잡는 자리가 있습니다. 문제 자체를 잘못 옮겨 적은 경우입니다. 문제가 $$\displaystyle\int_0^2 x e^x\,dx$$ 인데 공책에 위끝을 1로 적었다고 합시다. 손으로 풀면 1이 나오고, `sp.integrate` 에 같은 식을 넣어도 1, 리만합으로 재도 1 근처가 나옵니다. 세 길이 나란히 합격을 줍니다. 원래 문제의 답은 $$1 + e^2 \approx 8.389$$ 인데도 말입니다.

기계는 내가 넣은 식을 채점할 뿐, 그 식이 원래 문제와 같은지는 모릅니다. 그래서 채점에 들어가기 전에 원래 문제와 내가 옮긴 식을 한 글자씩 맞대 보는 일을 따로 둡니다. 특히 적분의 위끝·아래끝, 시그마의 시작과 끝, 지수의 부호처럼 한 글자로 뜻이 바뀌는 자리를 봅니다.

## 수치 검산

### 특수값 대입

기호로 안 풀리거나 결과가 너무 복잡하면 값으로 갑니다. 3번의 숫자 넣기가 여기 그대로 옵니다.

가장 싼 방법은 **특수값**, 곧 계산이 쉬운 $$x = 0$$, $$1$$, $$-1$$ 같은 값을 양변에 넣어 보는 것입니다. 값이 하나라도 갈리면 그 자리에서 틀린 것이 확정됩니다. 다만 모두 맞아도 참이라는 보장은 없습니다 — 세 점에서만 겹치는 다른 식도 있기 때문입니다. 그래서 여러 점에서 재어 그래프로 겹쳐 보는 편이 낫습니다.

여러 점에서 재려면 기호 식을 보통의 파이썬 함수로 바꿔야 합니다. `sp.lambdify` 가 그 다리입니다.

```python
import math

g = sp.lambdify(x, sp.diff(x**2*sp.sin(x), x), 'math')
g(1.0)                          # 2.2232442754839328
2*math.sin(1) + math.cos(1)     # 2.2232442754839328
```

`g` 는 이제 수를 넣으면 수가 나오는 함수라 수천 개의 점에 넣어도 빠릅니다. 기호 길에서 얻은 식을 수치 길의 도구에 그대로 물릴 수 있으니, 아래의 중심차분·리만합과 짝을 지어 "기호로 구한 도함수"와 "값으로 잰 기울기"를 맞댈 수 있습니다.

### 중심차분

[31번 · 도함수](/articles/math-basics-what-is-a-derivative)의 정의는 $$h$$ 를 한쪽으로만 보냈지만, 검산에는 양쪽을 쓰는 편이 훨씬 정확합니다. $$x$$ 의 양옆 두 점을 잇는 할선의 기울기로 도함수를 어림하는 이 방법을 **중심차분**이라고 합니다.

$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h}$$

![f(x−h)와 f(x+h)를 잇는 할선의 기울기가 접선의 기울기에 가까운 것](/assets/posts/math-basics-symbolic-checking-central-difference.svg)

```python
def central(f, x, h):
    return (f(x + h) - f(x - h)) / (2 * h)

central(math.sin, 1, 0.01)   # 0.5402933008747335
math.cos(1)                  # 0.5403023058681398
```

앞의 네 자리 $$0.5402$$ 까지 같습니다. [47번 · 자릿수와 오차](/articles/math-basics-orders-of-magnitude-and-error)의 상대오차로 재면 $$1.7 \times 10^{-5}$$ 이라 약 4~5자리가 맞았습니다. $$h$$ 를 10분의 1인 $$0.001$$ 로 줄이면 상대오차가 $$1.7 \times 10^{-7}$$ 로 100분의 1이 됩니다 — 중심차분의 오차가 $$O(h^2)$$ 이라는 뜻입니다.

### 최적의 h

그렇다면 $$h$$ 를 끝없이 줄이면 끝없이 정확해질까요. 직접 재 봅니다.

```python
for k in range(1, 14):
    h = 10.0**-k
    err = abs(central(math.sin, 1, h) - math.cos(1)) / math.cos(1)
    print(k, f"{err:.1e}")
# 1 1.7e-03   2 1.7e-05   3 1.7e-07   4 1.7e-09   5 2.1e-11
# 6 5.1e-11   7 3.6e-10   8 4.8e-09   9 5.5e-09  10 1.1e-07
# 11 2.2e-06  12 2.3e-05  13 3.3e-04
```

$$h = 10^{-4}$$ 까지는 $$h$$ 를 10분의 1로 줄일 때마다 오차가 100분의 1로 깔끔하게 줄어듭니다. 그런데 $$10^{-5}$$ 에서 바닥을 찍고는 다시 커지기 시작해, $$h = 10^{-13}$$ 에서는 $$h = 0.1$$ 일 때보다 오히려 나쁩니다.

![h를 줄일수록 상대오차가 내려가다 h = 10⁻⁵ 근처에서 바닥을 찍고 다시 오르는 V자](/assets/posts/math-basics-symbolic-checking-error-vs-h.svg)

오차가 두 갈래이기 때문입니다. 하나는 할선으로 접선을 어림하면서 생기는 **절단 오차**입니다. 테일러 전개의 뒤쪽 항을 잘라 낸 만큼이라 $$h^2$$ 에 비례하고, $$h$$ 를 줄이면 줄어듭니다. 다른 하나는 기계가 수를 16자리에서 자르면서 생기는 **반올림 오차**입니다. $$h$$ 가 아주 작으면 $$f(x+h)$$ 와 $$f(x-h)$$ 가 거의 같은 수가 되고, 그 둘을 빼면 47번의 자릿수 소거가 일어납니다. 남은 몇 자리마저 아주 작은 $$2h$$ 로 나누니 오차가 $$\tfrac{1}{h}$$ 에 비례해 불어납니다.

$$h$$ 를 줄이면 앞의 것은 줄고 뒤의 것은 늘어나므로, 둘의 합은 어딘가에서 가장 작아집니다. 그림의 두 점선이 만나는 근처, 여기서는 $$h = 10^{-5}$$ 언저리입니다. 정확한 자리는 함수와 점마다 조금씩 다르지만, 중심차분이라면 $$10^{-5}$$ 안팎을 쓰고 그보다 작게 줄이지 않는 것이 실전의 습관입니다. 로그-로그 축에서 왼쪽 비탈의 기울기가 2이고 오른쪽 비탈의 기울기가 1인 것도 47번에서 배운 대로 읽힙니다 — 각각 $$h^2$$ 과 $$\tfrac1h$$ 의 차수입니다.

### 중점법

[33번 · 정적분](/articles/math-basics-integral-as-area)에서 넓이를 직사각형으로 잘라 더했습니다. 그것을 그대로 적습니다. 각 조각의 가운데 높이를 쓰는 리만합이 **중점법**입니다.

```python
def riemann(f, a, b, n):
    w = (b - a) / n
    return sum(f(a + (i + 0.5) * w) for i in range(n)) * w

riemann(lambda t: t * math.exp(t), 0, 1, 100)    # 0.999981514413776
riemann(lambda t: t * math.exp(t), 0, 1, 1000)   # 0.9999998151431911
```

위에서 `sp.integrate` 가 준 $$1$$ 과 맞습니다. 조각을 10배로 늘렸더니 오차가 100분의 1이 되었으니 중점법의 오차도 $$O(h^2)$$ 입니다. 여기서 $$h$$ 는 조각 하나의 폭 `w` 입니다.

중점법도 조각을 끝없이 늘리면 결국 반올림 오차가 쌓이지만, 중심차분과 달리 비슷한 두 수를 빼는 자리가 없어 그 벽이 훨씬 멀리 있습니다. 조각 수 $$10^6$$ 정도까지는 늘리는 만큼 좋아진다고 봐도 됩니다.

## 난수 검산

### 확률의 추정

[39번 · 세는 법](/articles/math-basics-counting-and-binomial)의 생일 문제입니다. 서른 명의 생일을 실제로 10만 번 뽑아 봅니다. 이처럼 난수로 실험을 많이 되풀이해 확률을 재는 것을 **난수 검산**이라고 부르겠습니다.

```python
import random

hit = 0
for _ in range(100000):
    days = [random.randrange(365) for _ in range(30)]
    if len(set(days)) < 30:
        hit += 1
hit / 100000     # 0.70622
```

손계산 값은 $$0.70632$$ 였습니다. 상대오차가 $$1.7 \times 10^{-4}$$ 이라 약 3~4자리가 맞았습니다.

[38번 · 조건부확률](/articles/math-basics-conditional-probability-and-expectation)의 검사 문제도 같은 방법으로 잽니다. 10만 명을 만들어 양성인 사람만 세면 $$0.171$$ 이 나오고, 베이즈 정리로 얻은 $$1/6 \approx 0.1667$$ 과 앞의 두 자리가 맞습니다.

### 기댓값의 추정

확률이 아니라 평균, 곧 38번의 기댓값을 잴 때도 난수를 씁니다. 주사위를 1만 번 던져 눈의 평균을 내면 기댓값 $$3.5$$ 근처가 나와야 합니다. 같은 기댓값 $$3.5$$ 를 갖는 다른 실험도 하나 둡니다 — 동전을 던져 앞면이면 7, 뒷면이면 0을 받는 실험입니다.

```python
def mean_dice(seed, N=10000):
    random.seed(seed)
    return sum(random.randint(1, 6) for _ in range(N)) / N

def mean_coin(seed, N=10000):
    random.seed(seed)
    return sum(random.choice([0, 7]) for _ in range(N)) / N

[mean_dice(s) for s in range(5)]   # [3.4926, 3.505, 3.5041, 3.4756, 3.5064]
[mean_coin(s) for s in range(5)]   # [3.486, 3.4615, 3.5238, 3.5623, 3.5343]
```

다섯 번씩 재 보니 주사위 쪽은 $$3.5$$ 에서 많아야 $$0.024$$ 벗어났고, 동전 쪽은 $$0.062$$ 까지 벗어났습니다. 기댓값이 같은데도 동전 쪽이 훨씬 흔들립니다.

까닭은 [40번](/articles/math-basics-descriptive-statistics)의 표준편차에 있습니다. 한 번 던질 때 값이 평균에서 얼마나 흩어지는지를 재면 주사위가 약 $$1.71$$, 동전 실험이 $$3.5$$ 입니다. $$N$$ 번의 평균이 참값에서 벗어나는 폭은 대략

$$\frac{\text{표준편차}}{\sqrt{N}}$$

이라, $$N = 10000$$ 이면 주사위는 $$0.017$$, 동전은 $$0.035$$ 쯤입니다. 위의 다섯 번이 그 폭의 한두 배 안에 들어와 있습니다. 같은 횟수를 돌려도 한 번 한 번이 흩어진 실험일수록 평균은 덜 정확합니다.

### 자릿수의 한계

난수 검산이 사 주는 자릿수에는 한계가 있습니다. 확률을 잴 때도 위 식이 그대로 적용되어, 재려는 확률이 너무 작지만 않으면 $$N$$ 번 돌려 얻는 상대오차는 대략 $$1/\sqrt{N}$$ 의 크기입니다. 10만 번이면 $$0.3$$ % 남짓 — 두세 자리입니다. 자릿수를 하나 더 얻으려면 회수를 100배로 늘려야 합니다. 중심차분이 $$h$$ 를 10분의 1로 줄일 때마다 두 자리씩 사 준 것과 견주면 아주 느린 길입니다.

![10만 번이 사 주는 자릿수와, 로또 1등이 왜 이 방법으로 안 잡히는가](/assets/posts/math-basics-symbolic-checking-monte-carlo-limit.svg)

그래서 안 되는 것도 있습니다. 39번의 로또 1등 확률은 $$1 / 8{,}145{,}060 \approx 1.2 \times 10^{-7}$$ 입니다. 10만 번을 뽑으면 1등이 나올 기댓값이 $$0.012$$ 회라 거의 언제나 0회가 나오고, 추정값은 0이 됩니다. 대신 확률이 큰 사건으로 옮겨 재면 됩니다 — 6개 중 3개가 맞을 확률은 손계산으로

$$\frac{C(6,3)\,C(39,3)}{C(45,6)} = \frac{20 \times 9139}{8145060} \approx 0.02244$$

이고, 10만 번을 뽑으니 $$0.02305$$ 가 나와 두 자리가 맞았습니다. 재려는 확률의 역수보다 훨씬 많이 뽑아야 잴 수 있다 — 이것이 난수 검산의 조건입니다.

한 가지 더, 난수 검산은 한쪽 말만 믿을 수 있습니다. 손 답이 $$0.5$$ 인데 10만 번이 $$0.62$$ 를 냈다면 차이가 흔들림의 폭보다 수십 배 크니 손 답이 틀렸다고 꽤 확신할 수 있습니다. 그러나 $$0.70622$$ 가 $$0.70632$$ 와 맞았다고 해서 손 답이 정확히 맞았다고는 못 합니다. 참값이 $$0.7065$$ 였어도 같은 결과가 나왔을 것이기 때문입니다. 난수는 "어긋난다"를 보일 수 있지만 "맞다"는 그 폭 안에서만 말합니다.

### 시드 고정

난수는 돌릴 때마다 다르게 나오므로, 어제 본 $$0.70622$$ 를 오늘 다시 얻으려면 장치가 필요합니다. 난수를 만드는 출발점을 **시드**라고 하고, `random.seed(0)` 처럼 시드를 정해 두면 그 뒤로 나오는 난수의 줄이 매번 똑같습니다.

```python
random.seed(0); [random.randrange(365) for _ in range(3)]   # [197, 215, 20]
random.seed(0); [random.randrange(365) for _ in range(3)]   # [197, 215, 20]
```

시드를 고정하면 검산 결과를 다른 사람이 그대로 재현할 수 있고, 손 풀이를 고친 뒤 다시 돌렸을 때 달라진 것이 손 풀이 때문인지 난수 때문인지 가릴 수 있습니다. 위의 `mean_dice` 가 시드를 받는 것도 그래서입니다. 다만 시드 하나만 믿으면 그 시드가 우연히 좋은 쪽으로 나왔을 수 있으니, 위처럼 시드를 몇 개 바꿔 흔들림의 폭까지 함께 봅니다.

## Σ와 반복문

### 두 축의 순서

[27번 · 시그마 표기](/articles/math-basics-sequences-and-sigma)의 이중합을 코드로 옮기면 첨자를 놓치기 쉽습니다. 같은 합을 두 축 순서로 더해 값이 같은지 봅니다.

```python
a = [[1, 2, 3], [4, 5, 6]]
by_row = sum(sum(row) for row in a)                       # 21
by_col = sum(sum(row[j] for row in a) for j in range(3))  # 21
```

3번의 두 방법으로 세기를 코드로 옮긴 것입니다. 값이 갈리면 첨자를 잘못 옮긴 것입니다. 어떤 조건에서 합의 순서를 바꿔도 되는가라는 규칙 자체는 중급 3번의 몫이고, 여기서는 두 값이 같은지 보는 데까지입니다.

### 첨자의 시작점

시그마는 보통 1부터 세는데, 파이썬의 `range` 는 0부터 셉니다. $$\displaystyle\sum_{k=1}^{10} k$$ 를 옮기며 `range(10)` 을 쓰면 0부터 9까지를 더하게 됩니다.

```python
sum(k for k in range(10))        # 45   0, 1, …, 9
sum(k for k in range(1, 11))     # 55   1, 2, …, 10
```

![시그마의 k = 1부터 10까지와 range(10)의 0부터 9까지가 한 칸씩 어긋나는 모습](/assets/posts/math-basics-symbolic-checking-off-by-one.svg)

앞에서 0이 하나 끼고 끝에서 10이 하나 빠져, 합이 10만큼 모자랍니다. 이처럼 세는 범위가 한 칸 어긋나는 실수를 **오프바이원**이라고 합니다. 27번에서 자리를 0부터 세면 일반항이 한 칸 밀린다고 했던 바로 그 어긋남이 코드에서 일어난 것입니다.

잡는 방법은 둘입니다. 하나는 27번에서 구한 닫힌 꼴처럼 손으로 아는 값과 맞대는 것입니다 — $$1$$ 부터 $$n$$ 까지의 합은 $$\tfrac{n(n+1)}{2}$$ 이라 $$n = 10$$ 이면 55입니다. 다른 하나는 극단값입니다. 3번의 극단값 보기처럼 $$n = 1$$ 을 넣으면 시그마는 $$1$$ 하나뿐이어야 하는데, `range(1)` 은 0 하나만 돌아 합이 0입니다. 작은 $$n$$ 하나로 어긋남이 드러납니다.

### 빈 합

27번에서 위끝이 아래끝보다 작아 한 번도 돌지 않는 합을 빈 합이라 하고 0으로 둔다고 했습니다. 코드에도 같은 약속이 들어 있습니다.

```python
total = 0
for k in range(5, 5):    # 한 번도 돌지 않는다
    total += k
total                    # 0
sum([])                  # 0
```

합을 쌓을 때 `total = 0` 에서 출발하는 것이 곧 빈 합이 0이라는 약속입니다. 한 번도 돌지 않으면 출발값이 그대로 답이 되기 때문입니다. 손 풀이에서 빈 합을 1로 두었거나 코드에서 첫 항으로 출발값을 잡았다면, 범위가 빈 경우에서 둘이 갈립니다. 시작과 끝이 같은 경우를 하나 넣어 보는 것이 이 자리의 검산입니다.

## 연습 문제

### 연습 1 — 기호 검산 읽기

1. 두 식을 `sp.simplify(a - b) == 0` 으로 대조해 `True` 를 얻었는데도 두 식이 같지 않을 수 있습니다. 어떤 경우인지 예를 하나 들어 답하세요.

   답. 정의역이 다를 때입니다. $$\dfrac{x}{x}$$ 와 $$1$$ 은 차가 0으로 정리되지만 $$x = 0$$ 에서는 앞의 식이 정의되지 않습니다. 대조가 `True` 라도 "어떤 $$x$$ 에서 같은가"는 따로 봐야 합니다.
2. 손으로 $$\dfrac{d}{dx}\sin(3x) = \cos(3x)$$ 를 얻어 대조했더니 어긋났습니다. 의심 순서의 몇 번째 항목인지 답하고 옳은 답을 적으세요.

   답. 두 번째, 연쇄법칙의 속미분입니다. 안쪽 $$3x$$ 를 미분한 3이 빠졌으므로 옳은 답은 $$3\cos(3x)$$ 입니다.
3. 손으로 $$\displaystyle\int_0^1 6x^2\,dx = 6$$ 을 얻어 `sp.integrate` 와 대조했더니 어긋났습니다. 옳은 값을 구하고 어디가 빠졌는지 적으세요.

   답. $$\displaystyle\int_0^1 6x^2\,dx = \left[2x^3\right]_0^1 = 2$$ 입니다. $$x^2$$ 의 부정적분이 $$\dfrac{x^3}{3}$$ 인데 3으로 나누는 것을 빠뜨렸습니다.

### 연습 2 — 수치로 확인하기

1. 중심차분으로 $$f(x) = x^3$$ 의 $$x = 2$$ 에서의 도함수를 $$h = 0.1$$ 로 손계산하고, 참값과의 절대오차를 구하세요.

   답. $$\dfrac{2.1^3 - 1.9^3}{0.2} = \dfrac{9.261 - 6.859}{0.2} = \dfrac{2.402}{0.2} = 12.01$$ 입니다. 참값은 $$3x^2 = 12$$ 이므로 절대오차가 $$0.01$$ 입니다.
2. 1번에서 $$h$$ 를 $$0.05$$ 로 줄이면 오차가 대략 얼마가 될지 47번의 차수 표기로 근거를 적고 예상 값을 답하세요.

   답. 중심차분의 오차는 $$O(h^2)$$ 이므로 $$h$$ 를 반으로 줄이면 오차는 넷으로 나뉘어 약 $$0.0025$$ 입니다. 실제로 $$\dfrac{2.05^3 - 1.95^3}{0.1} = \dfrac{1.20025}{0.1} = 12.0025$$ 로 오차가 정확히 $$0.0025$$ 입니다.
3. 중점 리만합으로 $$\displaystyle\int_0^1 x\,dx$$ 를 $$n = 2$$ 로 손계산하고 참값과 견주세요.

   답. 폭이 $$0.5$$ 이고 두 조각의 가운데는 $$0.25$$ 와 $$0.75$$ 이므로 $$(0.25 + 0.75) \times 0.5 = 0.5$$ 입니다. 참값 $$\dfrac12$$ 와 정확히 같습니다 — 일차함수에서는 가운데 높이가 조각의 평균 높이와 같기 때문입니다.

### 연습 3 — 난수 검산과 이중합

1. 난수 10만 번으로 잰 값이 $$0.3327$$ 이고 손계산이 $$0.33333$$ 이었습니다. 상대오차를 구하고 몇 자리가 맞았는지 답하세요.

   답. $$\dfrac{|0.3327 - 0.33333|}{0.33333} = \dfrac{0.00063}{0.33333} \approx 1.9 \times 10^{-3}$$ 입니다. $$-\log_{10}(1.9 \times 10^{-3}) \approx 2.7$$ 이므로 약 2~3자리가 맞았습니다.
2. 확률이 $$1.2 \times 10^{-7}$$ 인 사건을 난수 10만 번으로 재려 하면 어떤 값이 나오는지와 그 까닭을 적으세요.

   답. 10만 번에서 그 사건이 나올 기댓값이 $$100000 \times 1.2 \times 10^{-7} = 0.012$$ 회라 거의 언제나 0회가 나오고 추정값이 0이 됩니다. 재려면 뽑는 횟수가 확률의 역수인 약 800만보다 훨씬 커야 합니다.
3. 이중합을 코드로 옮겨 놓고 첨자를 제대로 옮겼는지 코드만으로 한 번 더 확인하는 방법을 적으세요.

   답. 더하는 축의 순서를 바꿔 행부터 더한 값과 열부터 더한 값을 견줍니다. 두 값이 갈리면 첨자를 잘못 옮긴 것입니다.

### 연습 4 — 기호로 안 되면 수치로

1. `sp.integrate(sp.exp(-x**2), (x, 0, 1))` 은 초급에서 다루지 않은 특수함수 `erf` 로 답해 값이 바로 읽히지 않습니다. 대신 $$\displaystyle\int_0^1 e^{-x^2}\,dx$$ 를 중점법으로 $$n = 2$$ 로 손계산하세요. $$e^{-0.0625} \approx 0.93941$$, $$e^{-0.5625} \approx 0.56978$$ 을 써도 됩니다. 그리고 `sp.N` 으로 얻은 참값 $$0.746824$$ 와 견주어 상대오차를 구하세요.

   답. 폭이 $$0.5$$ 이고 두 조각의 가운데가 $$0.25$$, $$0.75$$ 이므로 높이는 $$e^{-0.25^2} = e^{-0.0625} \approx 0.93941$$ 과 $$e^{-0.75^2} = e^{-0.5625} \approx 0.56978$$ 입니다. $$(0.93941 + 0.56978) \times 0.5 = 1.50919 \times 0.5 \approx 0.75460$$ 입니다. 상대오차는 $$\dfrac{0.75460 - 0.74682}{0.74682} \approx 1.0 \times 10^{-2}$$ 로 두 자리쯤 맞았습니다. 조각을 10개로 늘리면 $$0.74713$$ 이 되어 오차가 약 25분의 1로 줄어 $$O(h^2)$$ 과 맞습니다.
2. 기계가 방정식 $$x^3 + x - 1 = 0$$ 의 해로 $$0.6823$$ 을 냈습니다. 먼저 $$0.68$$ 과 $$0.69$$ 를 좌변에 넣어 값을 구하고, 그다음 $$0.6823$$ 을 넣은 값과 함께 이 답을 믿어도 되는지 판단하세요.

   답. $$0.68^3 + 0.68 - 1 = 0.314432 + 0.68 - 1 = -0.005568$$ 이고 $$0.69^3 + 0.69 - 1 = 0.328509 + 0.69 - 1 = 0.018509$$ 입니다. 좌변이 음수에서 양수로 바뀌었고 그래프가 끊기지 않으므로 그 사이 어딘가에서 0을 지납니다. $$0.6823$$ 을 넣으면 $$0.317633 + 0.6823 - 1 \approx -0.0000666$$ 으로 0에 아주 가깝습니다. 해가 $$0.68$$ 과 $$0.69$$ 사이에 있고 대입한 값도 0에 가까우니 믿어도 됩니다.
3. `sp.limit((1 - sp.cos(x))/x**2, x, 0)` 이 $$\tfrac12$$ 를 냈습니다. $$\cos 0.1 \approx 0.99500417$$, $$\cos 0.01 \approx 0.99995000042$$ 를 써서 $$h = 0.1$$, $$0.01$$ 일 때 $$\dfrac{1 - \cos h}{h^2}$$ 를 손으로 구해 기호 극한과 대조하세요. 또 기계에 $$h = 10^{-8}$$ 을 넣었더니 $$0$$ 이 나왔습니다. 그 까닭을 적으세요.

   답. $$h = 0.1$$ 이면 $$\dfrac{1 - 0.99500417}{0.01} = \dfrac{0.00499583}{0.01} = 0.499583$$, $$h = 0.01$$ 이면 $$\dfrac{1 - 0.99995000042}{0.0001} = \dfrac{0.00004999958}{0.0001} = 0.4999958$$ 로 $$\tfrac12$$ 에 다가가 기호 극한과 맞습니다. $$h = 10^{-8}$$ 에서는 $$1 - \cos h$$ 의 참값이 약 $$5 \times 10^{-17}$$ 로, 1에 비해 16자리보다 더 아래의 차이입니다. 기계는 $$\cos h$$ 를 정확히 $$1$$ 로 반올림해 담고, 그래서 분자가 $$1 - 1 = 0$$ 이 됩니다. 비슷한 두 수를 빼는 자릿수 소거가 끝까지 간 것이고, 표를 만들 때 $$h$$ 를 너무 작게 잡으면 안 되는 까닭입니다.

## 정리

- 채점하는 길은 둘입니다. 기호 계산은 식을, 수치 검산은 값을 견줍니다. 손으로 먼저 풀고 기계로 채점합니다.
- 기호 검산의 관용구는 `sp.simplify(a - b) == 0` 입니다. SymPy의 `==` 는 구조 비교라 같은 식에도 `False` 를 낼 수 있습니다.
- 분수는 `sp.Rational` 로 적습니다. 소수가 섞이면 차가 $$10^{-17}$$ 같은 작은 수로 남습니다.
- 두 답이 갈리면 부호 → 속미분 → 괄호 → 정의역 순으로 의심하고, 정리가 멈추면 음수를 섞은 무작위 대입으로 확인합니다. 문제를 잘못 옮겨 적은 것은 어떤 검산도 못 잡습니다.
- 중심차분과 중점법은 오차가 $$O(h^2)$$ 이라, 조각을 10배로 늘리면 오차가 100분의 1이 됩니다. 다만 중심차분은 $$h$$ 를 너무 줄이면 반올림 오차가 커지므로 $$10^{-5}$$ 안팎에서 멈춥니다.
- 난수 검산의 오차는 대략 표준편차 나누기 $$\sqrt{N}$$ 입니다. 10만 번이면 두세 자리이고, 재려는 확률의 역수보다 훨씬 많이 뽑아야 합니다. 시드를 고정해 재현하고, "어긋난다"만 확실히 믿습니다.
- 이중합은 두 축 순서로 더해 값을 견주고, `range` 의 시작점과 빈 합을 작은 $$n$$ 으로 확인합니다.
