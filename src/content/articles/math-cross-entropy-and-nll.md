학습 스크립트를 열면 손실은 대개 한 줄입니다.

```python
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)
```

이름은 «교차엔트로피»입니다. 그런데 [지난 글](/articles/math-maximum-likelihood)에서 범주분포를 가정하고 최대가능도를 밀어붙였을 때 떨어져 나온 것은 **음의 로그가능도**였습니다. 이름이 둘인데 코드는 하나입니다. 게다가 저 괄호 안의 `label_smoothing=0.1`은 유도 어디에도 없던 값입니다.

이 글에서 그 셋을 붙입니다. 교차엔트로피가 무엇인지 정의하고, 정답이 원-핫일 때 그것이 음의 로그가능도와 **글자 그대로 같은 식**이 됨을 보이고, 라벨 스무딩이 그 식의 어느 자리를 건드리는 조작인지까지 갑니다.

## 교차엔트로피 — 남의 분포를 믿고 값을 치를 때

[엔트로피 글](/articles/math-entropy-and-perplexity)에서 분포 $$p$$ 의 엔트로피를 $$H(p) = -\sum_i p_i \log p_i$$ 로 정의했습니다. 「$$p$$ 에서 사건이 나올 때 놀람 $$-\log p_i$$ 의 평균」이었습니다.

여기서 분포를 **둘**로 늘립니다. 사건은 $$p$$ 에서 나오는데, 놀람은 $$q$$ 를 믿고 잽니다.

> **정의.** 분포 $$p$$ 와 $$q$$ 의 **교차엔트로피**(cross entropy)는
> $$H(p, q) = \mathbb{E}_{i \sim p}\big[-\log q_i\big] = -\sum_i p_i \log q_i$$
> 이다.

$$H(p)$$ 와 다른 곳은 **로그 안쪽 하나뿐**입니다. 앞의 $$p_i$$ 는 「실제로 얼마나 자주 일어나는가」이고 로그 안의 $$q_i$$ 는 「우리 모델이 얼마나 그럴 것이라 보는가」입니다. 그래서 교차엔트로피는 **틀린 확률표를 믿고 부호화했을 때 드는 평균 비용**으로 읽힙니다.

어휘가 넷인 장난감으로 세어 봅시다. 실제 분포는 $$p = (0.5,\, 0.25,\, 0.125,\, 0.125)$$ 이고, 이 분포의 엔트로피는 앞 글에서 1.75비트로 계산했습니다. 여기에 모델을 셋 대 봅니다.

![같은 p에 세 모델 분포를 대면 교차엔트로피가 갈린다](/assets/posts/math-cross-entropy-and-nll-two-distributions.svg)

**모델이 정확할 때.** $$q = p$$ 이면 $$H(p,q) = H(p) = 1.75$$ 비트입니다.

**모델이 아무것도 모를 때.** $$q = (0.25, 0.25, 0.25, 0.25)$$ 이면 놀람이 전부 2비트이므로

$$H(p, q) = 2\sum_i p_i = 2 \text{ 비트}$$

**모델이 거꾸로 알 때.** $$q = (0.125, 0.125, 0.25, 0.5)$$ 이면 놀람이 각각 3, 3, 2, 1비트이므로

$$H(p, q) = 0.5(3) + 0.25(3) + 0.125(2) + 0.125(1) = 2.625 \text{ 비트}$$

셋 다 $$H(p) = 1.75$$ 보다 크거나 같고, **$$q = p$$ 일 때만 등호**입니다. 이것이 우연이 아니라는 것 — 초과분 $$H(p,q) - H(p)$$ 가 언제나 0 이상이라는 것 — 은 중급 30번 · KL 발산이 증명합니다. 지금은 두 가지만 챙기면 됩니다. **교차엔트로피는 최소화할 대상으로 쓸 수 있고, 그 최솟값은 $$q$$ 를 $$p$$ 에 맞췄을 때 나온다.**

## 원-핫 정답을 넣으면 항 하나만 남는다

분류에서 정답은 분포가 아니라 클래스 하나입니다. 그래도 분포로 적을 수는 있습니다. 정답 자리만 1이고 나머지가 0인 벡터를 **원-핫**(one-hot) 분포라고 합니다 — 「$$y$$ 번 클래스가 확률 1로 일어난다」고 믿는 분포입니다.

어휘 넷에 정답이 2번 클래스라면 $$p = (0, 1, 0, 0)$$ 입니다. 이것을 정의에 그대로 넣습니다.

$$H(p, q) = -\sum_{i} p_i \log q_i = -\big(0 \cdot \log q_1 + 1 \cdot \log q_2 + 0 \cdot \log q_3 + 0 \cdot \log q_4\big)$$

**0이 곱해진 항은 통째로 사라집니다.** 남는 것은 하나뿐입니다.

$$H(p, q) = -\log q_y$$

![원-핫 정답이 합을 한 항으로 접는다](/assets/posts/math-cross-entropy-and-nll-onehot-collapse.svg)

$$q = (0.5, 0.25, 0.125, 0.125)$$ 이고 정답이 2번이면 $$-\log_2 0.25 = 2$$ 비트, 자연로그로는 $$-\ln 0.25 = 1.386$$ 내트입니다.

그리고 오른쪽 식이 바로 지난 글의 마지막 줄입니다.

$$\arg\min_\theta \left(-\sum_{i=1}^{n} \log q_\theta(y_i \mid x_i)\right)$$

**같은 식에 이름이 둘 붙어 있었던 것**입니다. 부르는 방향이 달랐을 뿐입니다.

| 이름 | 어디서 왔나 | 무엇을 강조하나 |
| --- | --- | --- |
| 음의 로그가능도 | 최대가능도 추정 | 「이 데이터가 나올 가능도를 키운다」 |
| 교차엔트로피 | 정보이론 | 「정답 분포와 모델 분포의 거리를 줄인다」 |

프레임워크가 «교차엔트로피» 쪽 이름을 쓰는 이유는 실용적입니다. 정답이 원-핫이 **아닐 때도** 그대로 통하기 때문입니다. 지식 증류에서 교사 모델의 출력 분포를 정답 자리에 놓거나, 바로 다음 절의 라벨 스무딩처럼 목표 분포를 일부러 무디게 만들면 $$p$$ 는 더 이상 원-핫이 아니고 합이 항 하나로 접히지도 않습니다. 그때도 $$H(p,q) = -\sum_i p_i \log q_i$$ 는 그대로 성립합니다. **더 넓은 쪽 이름이 붙어 있는 셈**입니다.

## 라벨 스무딩 — 목표 분포를 바꾸는 조작

`label_smoothing=0.1`이 하는 일은 딱 하나입니다. **모델을 건드리지 않고 목표 분포 $$p$$ 를 바꿉니다.**

> **정의.** 클래스가 $$V$$ 개일 때 **라벨 스무딩**(label smoothing)은 원-핫 목표 $$p$$ 를 균등분포와 섞어
> $$p' = (1 - \varepsilon)\, p + \frac{\varepsilon}{V}\mathbf{1}$$
> 로 바꾸는 조작이다. $$\varepsilon$$ 은 섞는 정도이고 보통 0.1을 쓴다.

$$V = 4$$, $$\varepsilon = 0.1$$, 정답이 2번이면 정답 자리는 $$1 - 0.1 + 0.1/4 = 0.925$$ 이고 나머지 세 자리는 각각 $$0.1/4 = 0.025$$ 입니다.

$$p' = (0.025,\, 0.925,\, 0.025,\, 0.025)$$

![원-핫 목표와 스무딩된 목표](/assets/posts/math-cross-entropy-and-nll-label-smoothing.svg)

같은 모델 $$q = (0.5, 0.25, 0.125, 0.125)$$ 에 대한 손실을 다시 셉니다. 놀람은 각각 1, 2, 3, 3비트였으므로

$$H(p', q) = 0.025(1) + 0.925(2) + 0.025(3) + 0.025(3) = 0.025 + 1.85 + 0.15 = 2.025 \text{ 비트}$$

원-핫일 때의 2비트에서 아주 조금 올랐습니다. 그런데 **값이 조금 오른 것은 요점이 아닙니다.** 요점은 손실이 최소가 되는 자리가 어디로 옮겨 갔느냐입니다.

교차엔트로피 $$H(p,q)$$ 는 $$q$$ 를 $$p$$ 에 맞출 때 최소가 된다고 했습니다. 그러니

- **원-핫 목표**의 최소는 $$q = (0,1,0,0)$$ 입니다. 그런데 $$q$$ 는 softmax를 통과해 나온 값이라 정확히 1이 될 수 없습니다. [softmax 유도 글](/articles/math-softmax-derivation)에서 본 대로 $$q_y \to 1$$ 이 되려면 정답 로짓이 나머지보다 **무한히** 커져야 합니다. 학습은 끝까지 다다르지 못할 목표를 향해 로짓을 계속 벌립니다.
- **스무딩한 목표**의 최소는 $$q = p'$$ 이고, 이것은 도달 가능한 자리입니다. 정답과 오답의 확률비가 $$0.925/0.025 = 37$$ 이면 되므로, 필요한 로짓 차는 $$\ln 37 = 3.61$$ 로 **유한합니다.**

라벨 스무딩이 과신을 줄인다는 설명은 여기서 나옵니다. 모델을 규제한 것이 아니라 **목표를 도달 가능한 자리로 옮긴 것**입니다. 대신 값을 치릅니다. $$p'$$ 자체가 엔트로피를 가지므로 손실은 아무리 잘 맞혀도 0으로 안 내려가고, $$H(p')$$ 만큼에서 멈춥니다. **스무딩을 켜고 끈 두 학습의 손실 값을 맞대 놓고 비교할 수 없는 이유**가 이것입니다.

## 배치 손실은 무엇의 추정량인가

사전학습 로그에 찍히는 손실은 토큰 하나의 값이 아니라 배치 안 토큰들의 평균입니다.

$$\widehat{L} = \frac{1}{N}\sum_{t=1}^{N}\big(-\log q_\theta(x_t \mid x_{<t})\big)$$

이 값이 재고 있는 참값은 **데이터 전체에 대한 기댓값**입니다.

$$L = \mathbb{E}_{x \sim p_{\text{data}}}\big[-\log q_\theta(x \mid \text{문맥})\big] = H(p_{\text{data}},\, q_\theta)$$

즉 배치 손실은 이 기댓값을 표본평균으로 대신 잰 값입니다. 확률적으로 뽑은 표본의 평균으로 기댓값을 어림하는 이 방법을 **몬테카를로 추정**이라고 합니다.

![배치 평균은 기댓값을 겨냥한 흔들리는 화살이다](/assets/posts/math-cross-entropy-and-nll-batch-estimator.svg)

그렇게 보면 [분산과 표준오차 글](/articles/math-variance-and-sampling-error)의 결과가 그대로 적용됩니다. 토큰별 손실의 표준편차가 $$s$$ 일 때 배치 손실의 표준오차는 $$s/\sqrt{N}$$ 입니다. 토큰 손실의 표준편차가 2.0쯤이고 배치에 토큰이 2,048개 들어 있으면

$$\text{표준오차} = \frac{2.0}{\sqrt{2048}} = 0.044$$

입니다. **연속한 두 스텝에서 손실이 0.04쯤 오르내리는 것은 학습이 나빠진 것이 아니라 표본이 바뀐 것**입니다. 이 눈금을 갖고 있으면 로그를 읽을 때 잡음과 신호를 가릅니다.

## 세 눈금은 같은 값의 다른 옷이다

손실 하나를 세 가지로 적을 수 있습니다. 앞 글에서 다룬 환산이지만, 이제 그 값이 «교차엔트로피»라는 것을 알고 보게 됩니다.

| 눈금 | 식 | 손실 1.85일 때 |
| --- | --- | --- |
| 손실 (내트) | $$L$$ | 1.85 |
| perplexity | $$\exp(L)$$ | 6.36 |
| bits-per-token | $$L / \ln 2$$ | 2.67 |

**bits-per-token**은 토큰 하나를 적는 데 드는 평균 비트 수입니다. 셋은 로그의 밑과 지수를 바꾼 것일 뿐 재는 양이 같습니다. 다만 라벨 스무딩을 켰다면 이 환산에 단서가 붙습니다 — 그때의 손실은 $$H(p', q)$$ 라서 «다음 토큰을 몇 개 중에 고민하는가»가 아니고, perplexity로 옮겨 읽어도 그 뜻이 아닙니다. 보고용 perplexity는 스무딩 없이 다시 재야 합니다.

## 코드로 확인하기

```python
import numpy as np

def H(p, q):                                  # 비트 단위 교차엔트로피
    return -(p * np.log2(q)).sum()

q = np.array([0.5, 0.25, 0.125, 0.125])
p = np.array([0.5, 0.25, 0.125, 0.125])
print(H(p, q), H(p, np.full(4, 0.25)),
      H(p, np.array([0.125, 0.125, 0.25, 0.5])))   # 1.75 2.0 2.625

# ① 원-핫이면 항 하나로 접힌다
y = 1
onehot = np.eye(4)[y]
print(H(onehot, q), -np.log2(q[y]))               # 2.0 2.0

# ② 라벨 스무딩은 목표 분포를 바꾼다
eps = 0.1
smooth = (1 - eps) * onehot + eps / 4
print(smooth)                                     # [0.025 0.925 0.025 0.025]
print(round(H(smooth, q), 4))                     # 2.025
print(round(np.log(0.925 / 0.025), 4))            # 3.6109  필요한 로짓 차

# ③ 프레임워크의 CrossEntropyLoss는 softmax + (-log q_y)
z = np.array([1.0, 2.0, 0.5, -1.0])
qz = np.exp(z - z.max()); qz /= qz.sum()
print(round(-np.log(qz[y]), 4))                   # 0.4952  내트
```

세 번째 블록이 이 글의 결론을 코드로 적은 것입니다. 프레임워크가 로짓을 받아 하는 일은 softmax를 통과시켜 $$q$$ 를 만들고 **정답 자리 하나에 $$-\log$$ 를 씌우는 것**이 전부입니다.

## 정리

- **교차엔트로피 $$H(p,q) = -\sum_i p_i \log q_i$$** 는 엔트로피에서 로그 안쪽만 $$q$$ 로 바꾼 값이다. 「$$p$$ 에서 일어나는 일을 $$q$$ 를 믿고 적을 때의 평균 비용」이다.
- $$H(p,q) \ge H(p)$$ 이고 **등호는 $$q = p$$ 일 때만** 성립한다. 그래서 최소화할 대상이 된다.
- **정답이 원-핫이면 합이 항 하나로 접혀 $$-\log q_y$$ 가 된다.** 이것이 음의 로그가능도와 글자 그대로 같은 식이다.
- 프레임워크가 «교차엔트로피» 쪽 이름을 쓰는 것은 **목표가 원-핫이 아닐 때도 통하는 넓은 정의**이기 때문이다.
- **라벨 스무딩은 모델이 아니라 목표 분포를 바꾼다.** 최적점이 무한한 로짓 차에서 $$\ln\frac{1-\varepsilon+\varepsilon/V}{\varepsilon/V}$$ 라는 유한한 값으로 옮겨 온다.
- 스무딩을 켜면 손실의 바닥이 0이 아니라 $$H(p')$$ 이므로 **켠 학습과 끈 학습의 손실 값은 비교할 수 없다.**
- **배치 손실은 $$H(p_{\text{data}}, q_\theta)$$ 의 몬테카를로 추정량**이고, 표준오차 $$s/\sqrt{N}$$ 만큼 흔들린다. 그 폭 안의 변동은 잡음이다.

처음의 한 줄로 돌아갑니다. `nn.CrossEntropyLoss(label_smoothing=0.1)`은 이제 세 부분으로 읽힙니다. **CrossEntropy**는 목표 분포와 모델 분포를 대는 방식이고, 기본값인 원-핫에서는 그것이 음의 로그가능도로 접히며, **label_smoothing**은 그 목표 분포를 도달 가능한 자리로 옮기는 조작입니다. 5단원의 첫 세 편으로 사전학습 손실 한 줄의 유도가 여기서 닫혔습니다.

남은 것은 「그래서 두 분포가 얼마나 떨어져 있는가」를 재는 양입니다. 위에서 «초과분 $$H(p,q) - H(p)$$ 가 언제나 0 이상»이라고 적어 두고 증명을 미뤘는데, 그 증명에 필요한 도구를 다음 글이 먼저 세웁니다 — 볼록함수와 기댓값의 순서를 뒤집는 부등식 하나입니다.
